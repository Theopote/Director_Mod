## 1. 结论摘要

当前 Actor 功能覆盖面较广，编辑事务、采样隔离、持久化结构和测试基础整体已经比较完整。本次没有发现全量测试中的现有失败，但源码和临时探针仍暴露出以下需要处理的问题：

- **P1：3 项**。事件片段重进不触发、异步保存存在数据竞争和失败丢脏、角度归一化可能造成客户端假死。
- **P2：8 项**。动画事件长历史开销、村民手臂摆动抵消、跨出场姿态混合不一致、自定义模型预览 revision 不完整、原生模型层级映射不一致、Spawn 子区间越界、脚骨未参与 IK、非有限数值边界校验不统一。
- **P3：4 项**。可变 getter 的封装风险、`clearKeyframes()` 缺少采样失效、重复/未使用模型代码、运行时控制器职责过重。

建议先处理 P1 中的事件缓存和角度归一化，再重构 Actor/Path 的保存快照边界；姿态混合和 Spawn 裁剪策略需要先明确产品语义，避免只修表象。

## 4. P1 问题

### F-01 事件片段离开后无法再次触发

**优先级**：P1  
**证据**：已复现

**位置**

- `src/main/java/com/director/timeline/playback/entity/ActionTriggerCache.java:36-56`
- `src/main/java/com/director/timeline/playback/entity/EntityClipSampler.java:118`
- `src/main/java/com/director/timeline/playback/entity/EntityClipSampler.java:137-160`
- `src/main/java/com/director/timeline/playback/entity/EntityClipSampler.java:249-251`
- `src/main/java/com/director/timeline/playback/entity/EntityClipSampler.java:553-560`

**问题**

`ActionTriggerCache.shouldTrigger()` 设计为在时间离开 Clip 后删除触发记录，但采样器只把当前覆盖播放头的 `EntityActionClip` 交给缓存。播放头离开事件片段后，该 Clip 不再进入 `actionClips`，因此缓存中的 `if (!inside) triggered.remove(key)` 在正常离开场景不可达。

`clearActionCache()` 没有生产调用者，回拖时也没有清理 Action 缓存。

**复现**

- Spawn：`0..20`
- EntityActionClip：`2..4`
- `sampleAt(2)`：产生 1 个事件
- `sampleAt(5)`：不处理该事件，但缓存未清理
- 再次 `sampleAt(2)`：事件数为 0，预期为 1

**影响**

时间线循环、跳转后重进、同一事件片段再次播放时，攻击、声音、粒子、道具等事件可能丢失。

**修复方向**

- 每次事件采样维护当前活跃 Action Clip ID 集合，并删除已经离开的缓存项；或把轨道全部 Action Clip 交给缓存统一判断。
- 明确回拖和循环边界时的缓存重置规则。
- 增加“进入—离开—重进”“同片段内回拖”“循环播放”回归测试。

### F-02 Actor/Path 后台保存存在数据竞争、跨世界目标竞争和失败丢脏

**优先级**：P1  
**证据**：强代码证据，需并发压力测试

**位置**

- `src/main/java/com/director/actor/ActorRegistryManager.java:52-82`
- `src/main/java/com/director/actor/ActorRegistryManager.java:99-151`
- `src/main/java/com/director/actor/ActorRegistry.java:31-32`
- `src/main/java/com/director/actor/persistence/ActorRegistryPersistence.java:123-169`
- `src/main/java/com/director/actor/path/ActorPathLibraryManager.java:55-78`
- `src/main/java/com/director/actor/path/ActorPathLibraryManager.java:159-189`
- `src/main/java/com/director/actor/path/ActorPathLibrary.java:21`
- `src/main/java/com/director/actor/path/persistence/ActorPathPersistence.java:45-56`

**问题**

1. **活对象跨线程序列化**：后台保存线程直接遍历普通 `LinkedHashMap`、Actor、ActorGroup 和 Path 对象；编辑线程可以同时修改它们。`List.copyOf()` 只复制集合引用，不复制对象字段，不能形成一致快照。
2. **数量与内容可能不一致**：Actor 持久化先读取 `size()/groupSize()`，再分别遍历演员和群组；并发修改可能产生不一致文件。
3. **世界切换存在目标窗口**：世界切换时先替换 `GLOBAL`，随后才绑定新世界文件。已排队的后台任务可能读取到新 Registry，却使用旧的 `boundRegistryFile`，把新世界内容写入旧存档。
4. **失败后脏标记丢失**：异步任务在写盘前执行 `dirty.getAndSet(false)`，保存失败后不恢复 dirty，也没有自动重试。`saveImmediately()` 同样先清 dirty 再写盘。
5. **Path 持久化异常边界不完整**：只捕获 `IOException`，SaveGuard 或序列化中的 `RuntimeException` 可能从后台任务逸出。

**影响**

可能丢失最后一次编辑、保存不一致快照、把数据写入错误世界，或出现难以复现的后台保存异常。

**修复方向**

- 在编辑线程生成不可变 DTO 快照，同时捕获目标文件路径和世界/库代次；后台线程只写快照。
- 用单调 revision 或 dirty generation 管理保存版本，只有对应版本成功后才清除脏状态。
- 世界切换与保存任务使用同一代次/锁协调，旧任务不能写入新世界。
- 失败时恢复 dirty、提供重试和明确状态；Path 持久化统一捕获并报告运行时异常。
- 使用 CountDownLatch 构造“编辑—序列化—世界切换—写盘失败”并发测试。

### F-03 角度归一化可能被非有限值或极大有限值拖死

**优先级**：P1  
**证据**：强代码证据，未执行挂死探针

**位置**

- `src/main/java/com/director/timeline/playback/entity/EntityClipSampler.java:527-546`
- `src/main/java/com/director/timeline/playback/entity/EntitySample.java:368-387`
- `src/main/java/com/director/timeline/model/entity/EntityTransformClip.java:101-126`
- `src/main/java/com/director/timeline/model/entity/EntityClipKeyframe.java:70-72`
- `src/main/java/com/director/timeline/persistence/TimelineModelPersistence.java:1689-1691`
- `src/main/java/com/director/timeline/persistence/TimelineModelPersistence.java:1773-1776`

**问题**

角度归一化使用反复加减 `360f` 的 `while` 循环：

- Infinity 永远不会离开循环。
- 当有限值足够大时，浮点精度可能使 `a -= 360f` 不再改变 `a`，同样无法收敛。
- NaN 会跳过循环，但会继续污染采样结果。

属性编辑会话会拒绝 NaN/Infinity，但没有限制有限角度大小；模型 setter 和时间线 DTO 加载也没有统一有限值/范围防护，因此异常 API 输入或坏存档仍可进入采样路径。

**影响**

客户端采样/渲染线程可能长时间假死，或把 NaN 姿态继续传给渲染和 IK。

**修复方向**

- 在模型 setter 和持久化边界拒绝/回退非有限值。
- 对合法有限角度使用常量复杂度归一化，例如先判断有限值，再用 `% 360f` 调整到目标区间。
- 为 NaN、Infinity、`Float.MAX_VALUE` 和普通跨零角度增加测试。

## 5. P2 问题

### F-04 动画事件长历史投影可能抛异常并产生每帧高开销

**优先级**：P2  
**证据**：强代码证据，需性能实测

**位置**

- `src/main/java/com/director/timeline/playback/entity/AnimationEventClock.java:165-176`
- `src/main/java/com/director/timeline/playback/entity/EntityClipSampler.java:457-475`
- `src/main/java/com/director/timeline/model/entity/EntityAnimationClip.java:101-103`

**问题**

单次动画事件投影重复超过 100000 次会直接抛出未捕获的 `IllegalArgumentException`。动画速度虽限制在 `0.01..4`，但没有限制 Clip 时长、资产时长和循环次数的组合。

此外，只要存在 `SET_VISIBILITY` 事件，每帧都会从动画开始重新投影全部历史出现次数，以确定最后状态，开销随历史重复次数增长。

**影响**

长片段、短循环资产、高速度或距离驱动相位可能中断采样，或造成明显帧耗时。

**修复方向**

- 不要用未捕获异常中断播放；采用可诊断的降级、上限或事件压缩策略。
- 为状态事件维护最后出现位置/状态，避免每帧重算全部历史。
- 对事件批量查询和播放采样分别设置性能预算与测试。

### F-06 跨 Spawn 的前序拥有姿态不参与混合，独立姿态却会

**优先级**：P2  
**证据**：已复现，语义待定

**位置**

- `src/main/java/com/director/timeline/playback/entity/EntityClipSampler.java:130-135`
- `src/main/java/com/director/timeline/playback/entity/EntityClipSampler.java:258-261`
- `src/main/java/com/director/timeline/playback/entity/EntityClipSampler.java:602-644`

**问题**

采样器从完整轨道收集独立 `ActorPoseClip`，但只补入当前 active Spawn 拥有的 Pose。`applyActorPose()` 又从传入列表选择前序姿态。

因此旧 Spawn 拥有的 Pose 不能成为新 Spawn 首姿态的 previous；同一姿态改为独立 Pose 后就会参与混合。

**复现**

- 旧拥有姿态：head yaw `0`
- 新拥有姿态：head yaw `1`，区间 `3.2..4.8`
- `3.5s`：拥有姿态结果为 `1.0`
- 将旧姿态改为独立姿态后：`3.5s` 结果为 `0.18749996`

**影响**

仅改变姿态归属方式就会改变动画结果，用户难以预测跨出场过渡。

**修复方向**

先选择并记录一种语义：

- **轨道级混合**：收集所有 Spawn 的前序拥有姿态，与独立姿态使用同一规则。
- **生命周期隔离**：previous 限定在同一 Spawn，并排除跨生命周期的独立姿态。

随后补充跨 Spawn、独立/拥有姿态互换、重叠和静音测试。

### F-08 原生 ModelPart 没有完整消费逻辑 Rig 的父级变换

**优先级**：P2  
**证据**：强代码证据，渲染语义需实机确认

**位置**

- `src/main/java/com/director/actor/preview/NativeMobModelPose.java:47-55`
- `src/main/java/com/director/actor/preview/NativeMobPoseAngles.java:15-27`
- `src/main/java/com/director/actor/preview/NativeMobPoseAngles.java:67-85`
- `src/main/java/com/director/actor/rig/skeleton/QuadrupedRig.java:20-25`
- `src/main/java/com/director/actor/rig/skeleton/RigPose.java:129-139`

**问题**

逻辑 Rig 会累积父级旋转和 scale，但原生模型映射：

- 四足动物的 head 和四条腿全部 `followBody=false`，而逻辑 Rig 中它们都挂在 BODY 下。
- 人形 head/arms 只额外乘父旋转，不继承 body scale。
- `bodyPivotPixels()` 只旋转偏移，不处理父级 scale。

因此 `RigWorldPose`、脚部接触、注视和 IK 使用的层级可能与实际原生渲染不一致。

**影响**

身体缩放、身体俯仰以及依赖逻辑骨架的约束，可能在原生 Mob 上表现不完整或位置漂移。四足场景是否需要跟随身体，需结合 vanilla 模型层级和产品意图确认。

**修复方向**

- 统一逻辑骨架到原生 ModelPart 的矩阵映射，累积父旋转、scale 和 pivot；或明确声明哪些通道故意不继承，并让逻辑骨架采用同样规则。
- 对 body pitch/yaw/scale、head/arms、四足身体和腿部组合进行客户端截图回归。

### F-11 Path/ActorGroup 的非有限数值校验不统一

**优先级**：P2  
**证据**：强代码证据，坏存档/API 输入条件

**位置**

- `src/main/java/com/director/actor/ActorGroup.java:109-118`

**问题**

- `formationSpacing/delayStepSeconds` 只使用 `Math.max`，NaN 和 Infinity 可以通过。

**修复方向**

- 在 setter 和加载边界统一拒绝/回退非有限值。
- 对路径点返回防御性副本或不可变向量。

## 7. 已核对但不列为现行缺陷的事项

- `ActorClipPropertyEditSession.detached()` 当前已正确包含 `EntityActionClip` 分支，见 `src/main/java/com/director/ui/actor/edit/ActorClipPropertyEditSession.java:193`；`ActorPropSpawnPropertyEditSessionTest` 也覆盖了事件片段编辑。此前关于重复分支导致只读的结论已过期，不列入本报告。

## 8. 建议实施顺序

1. **快速修复**：F-01 Action 缓存离开清理；F-03 常量复杂度角度归一化与有限值防护。
2. **保存可靠性**：F-02 引入不可变快照、目标路径/世界代次和失败重试。
3. **播放与视觉正确性**：F-04、F-05、F-06、F-07、F-08，并在 Minecraft 客户端建立截图/交互回归。
4. **编辑不变量**：F-09 Spawn 子区间策略；F-10 footBone；F-11 数值边界。
5. **维护性清理**：F-12 至 F-15。

## 9. 最终评价

Actor 系统已经具备较完整的项目级模型、时间线采样、编辑事务和测试体系，当前主要风险集中在**事件缓存生命周期、跨线程保存快照、数值边界以及逻辑骨架与实际渲染语义的一致性**。优先修复 P1 可以显著降低播放错误和存档风险；姿态与 Spawn 区间问题则应先明确语义，再通过客户端回归验证，避免修复后仍存在显示与数据两套规则。
