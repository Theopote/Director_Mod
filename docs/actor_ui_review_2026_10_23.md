# Actor UI 检查与整改建议

日期：2026-10-23。检查当前源码与调用关系，包含演员浏览器、属性、工具、动画资产、路径、分组和时间线入口。没有运行 Minecraft 窗口，因此本文确认的是 UI 代码/操作链路问题；尺寸、遮挡、颜色、鼠标命中等视觉结果仍需游戏内验收。本轮只审查和记录，不修改运行时代码。

## 1. 应先修的交互问题

### P1-1 分组路径命令没有稳定的源演员选择

证据：`ActorProjectPropertyAdapter.renderGroupList` 选组时调用 ActorSelectionHub.clearSelection；同一适配器的 `renderGroupRouteAuthoring` 从 ActorSelectionHub.getSelectedActorId 获取源演员。clearSelection 最终把 currentActorId 设为 null。分组属性通过 ActorGroupPropertyAdapter 调用该命令区，但没有自己的源演员下拉框。

结果：正常从演员列表点击分组后，源演员为空，复制路径按钮不可用；再点击演员又可能切换属性目标。用户难以完成“指定源演员→给组复制路径”。

整改：分组命令独立保存源演员 ID，以带名称的下拉框选择；提供“使用当前演员”快捷按钮。只显示有可复制路径的候选，并说明源演员/锁定/冲突成员的跳过原因。选组不要依赖同时维持演员全局选择。切工程和源演员删除时清除失效引用。

### P1-2 动画资产库仍有新增独立演员动画片段的普通入口

证据：`ActorAnimationAssetPanel` 的“放到所选演员的播放头”调用 `ActorAnimationAssetEditing.attach`，明确 new EntityAnimationClip + EntityTimelineClip，加入 payload 和可见轨道。与此同时 `ActorSpawnPresetPropertyUI` 明确提示“绑定预设……不会创建额外片段”。

结果：同一用户目的“给演员使用动画”会得到两种不同的数据和时间线布局，容易重新产生用户反复报告的多片段困惑。

整改：普通入口改为“作为当前演员片段的动作预设”，要求明确选中生命周期片段；替换已有预设时显示原引用，保持手工关键帧。若保留独立动作片段，应放到明确的高级入口并说明它会新增片段。没有当前生命周期片段时导航选择，不自动创建。

关联问题：资产面板的 activeClip 只搜索顶层 EntityAnimationClip，因此同一面板的“当前片段/独立副本”信息不能稳定反映 Spawn 内嵌手工动画。应复用 ActorEmbeddedAnimation/ActorAnimationEditContext，而非再写一个顶层片段查找。

### P1-3 分组编辑、皮肤与模型设置没有统一撤销

证据：`ActorGroupPropertyAdapter` 直接 setName、setFormationType/Spacing、setDelayPolicy/Step、removeActor、removeGroup，并立即保存；`ActorProjectPropertyAdapter` 的创建组、演员分组勾选、玩家模型、弯曲模式和皮肤选择/清除也直接修改数据。演员重命名/类型和群体批量命令则已使用时间线命令。

结果：同一套界面中，一些操作可撤销，一些不能；用户按撤销会得到不一致结果。组删除后也应清除相关属性检查上下文，不能只清全局 selection。

整改：项目级演员/分组变更统一命令。文本在确认/失焦后提交，滑条一次手势一个命令。皮肤文件导入是外部资源操作，可独立说明，但“演员绑定哪张皮肤”应可撤销。不要用文件导入不能回滚来解释绑定也不能撤销。

### P1-4 群体语义动作展示了无效的循环选项

证据：`renderGroupActionAuthoring` 绘制 groupActionLoop 并传入 createActionClips；`EntityClipSampler.applyActorAction` 没有消费该 loop 参数。独立语义动作属性已经移除了同类无效控件。

结果：用户切换循环但看不到区别，容易与真正 AnimationAsset 的循环播放混淆。

整改：移除群体语义动作的循环控件，明确“动作持续整个所选区间；循环动画使用动作预设”。不需要因为 UI 有此开关就临时增加一套不同的循环语义。

## 2. 控制来源与编辑状态

### P2-1 控制来源说明仍在自行推断，尚未完全消费实际求解结果

`ActorBoneControlSource` 根据 sample.lookAtEnabled/strength 就宣称头部由注视控制，没有判断动态目标是否成功解析。它还通过临时默认姿态推算接触/换脚来源；最近新增的 ActorPoseEvaluator 已返回权重与诊断，但 UI 尚未全面使用这些结果。

结果：目标丢失时实际保留原动画，界面却可能显示“注视覆盖”；默认姿态上的接触判断也不等于当前最终姿态的实际修正。

整改：属性面板显示实际 evaluation 的贡献和未生效原因，区分“配置启用”与“本帧生效”。无需每帧在 UI 重跑完整 IK。注视部分权重允许保留原动画，现有“制作手工转头时请关闭注视”的文字应改为说明混合与权重，而不是一律建议关闭。

### P2-2 播放/拖动/草稿/锁定的可编辑规则分散

资产面板主要检查 playing/骨骼拖动/数值草稿；路径库主要检查 model==null/playing；群组基本属性则没有相同的禁用包围。部分服务还检查 scrubbing 和轨道锁定。

整改：共用编辑可用性描述，返回是否允许、原因和建议操作。按钮禁用前显示原因；可只读浏览列表，但不能因播放而把整个列表选择都禁用。资产、皮肤、分组等不同类别的允许范围应明确，不简单规定所有按钮永远同步禁用。

### P2-3 动画工具同时承担太多资产管理任务

`EditorToolPropertyAdapter.renderAnimationAuthoring` 同时显示编辑目标、自动关键帧、Gizmo 模式、资产 ID、新资产时长、插值、完整资产库和骨骼树。资产库又显示新建/复制 ID、导入 ID 等技术信息。

整改：工具区只保留当前操作方式和打帧设置；属性面板编辑当前演员/片段/部位；资产库独立负责资源管理。ID、导入导出和共享副本放高级区，日常使用以名称、用途、兼容骨架和共享状态为主。

## 3. 路径库问题

### P2-4 锁定状态与按钮反馈不一致

`ActorPathLibraryPanel.renderPathRow` 中重命名按钮仍可点击，但 locked 时直接不执行；删除按钮也没有同步禁用，而编辑服务会拒绝锁定路径。

整改：禁用不能执行的按钮，说明先解锁。显示/隐藏是否允许在锁定状态下改变需明确，避免把“编辑锁定”和“显示锁定”混为一谈。

### P2-5 窄面板缺少溢出策略

路径行固定预留四个 22px 控件，再使用 getContentRegionMaxX 减去控件区；面板太窄时 iconRegionStart 可落到行起点左侧，而 nameWidth 被设为 0（ImGui 通常将 0 宽视为自动占满）。需要实际窄窗口复测是否重叠/裁切。

整改：名称弹性占位，保留主要编辑按钮，其余放行菜单；最小宽度不足时换行。长名称提供完整悬停文本。

### P2-6 路径库选择状态与场景编辑状态分开存储

库内 selectedPathId、静态 selectionOwner 和控制器 editingLibraryPathId 分别维护。锁定路径点击只选库项目，不加载编辑；关面板/切页和路径场景点击后需要核验两处高亮是否一致。此项是状态同步风险，不直接判定目前所有路径点击都已失效。

整改：统一 PathSelectionContext，区分只选中、可编辑、正在拖动。显示“已隐藏但被选择”“已锁定”等状态，让场景没有曲线时有解释。

## 4. 已确认合理或不应误报的部分

- 主 ActorsPanel 的 projectView 仅显示演员/分组浏览器；选中演员的完整属性只在非 projectView 渲染。不能再笼统认为演员面板和属性面板把全部参数重复画了两遍。
- 演员删除确认由 DirectorUIManager 在 panelManager.renderPanels 之后调用全局 renderDeleteConfirmPopup。当前结构已处理旧的面板内弹窗问题，本轮没有证据断言它仍被遮挡或导致锁死。
- ActorTimelineAnimationPanel 的旧“演员骨骼动画”固定区域类仍在，但源码检索没有生产调用；不能把它列为现在实际出现的重复面板。可后续删除死入口以免重新接回。
- 路径库修改已通过 ActorPathEditing，动画资产主要操作已走命令，群体批量命令已有预览和整体撤销。应补齐剩余入口，而不是全部重写。
- 分组成员不是完全无法加入：当前从演员属性勾选所属组加入；组属性只展示和移除。建议在组属性补一个“添加成员”选择器，改善发现性。
- ActorSelectorPanel 是主适配器缺失时的备用列表，不等于日常有两个演员浏览器。它持有固定 Registry/Timeline，需要后续清理或补重绑定，但优先级低于主流程。

## 5. 建议的 UI 归属

| 区域 | 主职责 |
| --- | --- |
| 演员面板 | 演员/分组/路径浏览、搜索、创建、选择、放置、资源状态 |
| 工具面板 | 整体/部位/路径工具，移动/旋转/缩放、坐标系、自动打帧 |
| 属性面板 | 当前对象：资产基础信息，片段预设/路径/约束，选中部位 TRS；按上下文切换 |
| 时间线 | 演员生命周期片段、骨骼通道关键帧、时间/插值/选择与编辑反馈 |
| 动画资产库 | 姿态/动作资源、兼容过滤、共享关系、导入导出和独立化 |

演员、分组和路径数量多时，浏览列表需独立滚动，创建按钮固定在工具条。当前“演员与分组”同页可以先保留，但应避免长演员列表把分组和创建按钮挤出可见区域。复杂玩家与其他生物共用基本入口，通过能力过滤部位/动作，而不是把全部高级控件一律展示。

## 6. 推进顺序与验收

1. 分组独立选择源演员；收敛资产“应用动画”入口；移除无效群体循环控件。
2. 分组/皮肤/模型/弯曲模式等项目属性补统一命令与手势提交。
3. 实际求解结果反馈、统一只读原因、锁定按钮和路径窄布局。
4. 工具/属性/资产职责整理，清理未挂接的旧面板和备用入口。

验收场景：选演员→选组→明确选源路径并批量应用；使用已有动画不增加意外片段；改组属性/换皮肤/弯曲模式后一次撤销恢复；缺失注视目标显示未生效原因；锁定路径不能假点击；窄窗口控件不重叠；播放与拖动时编辑限制清楚；切工程和撤销后选择目标有效。

本轮没有新增或运行自动测试，也没有声称完成游戏内视觉检查。上述确认项来自具体源码链路，布局和弹窗实际效果应单独验收。
