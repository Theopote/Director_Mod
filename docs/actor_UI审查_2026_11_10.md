# 演员（Actor）界面审查

日期：2026-11-10。审查对象是当前工作区 `e332c59b`（`refactor(playback): 统一路由查找逻辑，消除编辑器与播放器重复`）。工作区另有一处未提交改动：`ActorGroupTimelineCommandService.java` 删除了 17 行，该文件不负责界面，下面的结论不依赖这处差异。

范围是演员浏览器、属性面板、姿态与变换工具页、片段检查器、时间线轨道和骨骼行。本轮按当前源码重新阅读，不把 2026-11-02 的属性面板审计或 2026-11-06 的逻辑审查原样当成现状。没有修改产品代码，没有启动 Minecraft，也没有在游戏里点过这些面板。

逻辑缺陷仍以 `docs/actor_代码审查_2026_11_06.md` 为准。那份报告写于 `8af77ac8`，其后已有片段 ID、离场持续和状态覆盖的提交；本报告只在界面文案和当前源码对得上时引用它们。

## 总评

演员相关界面能完成身份、出场、姿态、变换和关键帧编辑，撤销路径也大多接到了创作服务。问题在信息架构：同一件事有两三个入口，属性面板又用整页替换决定“现在该看什么”。默认布局里找不到演员列表。点中演员轨道时，打开的是演员档案，轨道的静音和锁定不在这一页。时间线上骨骼关键帧的菱形按播放时钟投影，松手后播放头却按匀速公式跳。

建议先收口面板职责，再改单页上的控件密度。下面按这个顺序写。

## 当前界面怎么分流

属性面板 `PropertiesPanel.doRender` 的优先级是：

1. 整体关键帧检查占住整页（`ActorRootKeyPropertyUI`）。
2. 骨骼关键帧处于焦点时占住整页（`ActorKeySelectionPropertyUI`）。
3. `PropertyContextService.getActorInspection()` 有演员或分组时，画对应档案。显式检查来自列表点击后的 `inspectActorObject`。没有显式检查、选择类型是 `ACTOR`、且没有非选择工具时，退回当前选中的演员。
4. 其余按最近一次交互在工具页和时间线对象之间切换。

几条实际路径：

| 操作 | 属性面板看到的内容 |
| --- | --- |
| 世界里点演员 | `ActorPickController` 走 `selectWholeActor`：清骨骼焦点和关键帧选择，激活选择工具，再选中演员。没有其他工具时显示身份档案。 |
| 演员列表里点一行 | `selectActor` 后立刻 `inspectActorObject`。身份档案盖住当前工具页，姿态工具不会被关掉。 |
| 点中演员轨道 | 选择类型是轨道，显式检查被清掉。`getContextTarget` 把演员轨道换成 `Actor` 对象，于是仍画身份档案。 |
| 点中片段 | 显式检查被清掉，画该片段的检查器。 |
| 点中整体键或让骨骼键获得焦点 | 整页换成对应的键检查器。 |
| 没有选择 | `renderProjectPanel` 只显示未选择提示。演员浏览器不在这里。 |

演员浏览器在 `ActorsPanel`，标签是「演员与分组」「路径库」和场景诊断。这个窗口 `setVisible(false)`，默认布局不打开，要从「窗口」菜单调出来。删除确认弹窗由 `DirectorUIManager` 用浏览器那份适配器画，不依赖属性面板。

姿态工具页在身份档案之外再画一遍姿态图库，并默认展开「关键帧动画」（编辑目标、自动键、Gizmo、插值、资产面板、骨骼数值、Dope Sheet）。语义动作和局部姿态收在「更多」里。变换 Gizmo 工具另画一份实时变换。

时间线展开演员轨道后，先画整体位移/旋转/缩放子行，再按骨架画骨骼行。`ActorTimelineAnimationPanel`（时间线里的第二块骨骼动画区）没有任何调用。

## 已经对得上的部分

这些行为与当前源码一致，本报告不把它们再列为缺陷。

- 片段检查器在播放、拖播放头、锁定或禁用时保留参数，并写明只读原因。根关键帧和骨骼关键帧检查器同样有只读说明。
- 多选骨骼键可以一起改时间和插值，不把不同部位的数值合成一个数。多选整体键的数值编辑要求先收成单键，时间仍在时间线上拖。
- 右键新建片段走 `AddEntityClipCommand`。姿态工具里的语义动作和局部姿态走 `ActorTrackClipAuthoringService`。两条都进撤销。
- 动画片段可以不绑定动作。下拉默认文案是「选择动作」，并说明选中后才参与播放。
- 状态片段的发光是「继承 / 开启 / 关闭」，可见性要先勾覆盖再调滑条。潜行、冲刺、无敌保持禁用，并有未接入预览的说明。
- 离场文案是「在片段结束时生效，持续到下一次出场」。`ActorTrack.hasCompletedDespawn` 对隐藏和移除都是结束后一直生效，直到下一次出生接上。文案和这条规则一致。
- 第二预设写明不能以全权重、全骨骼、全通道覆盖同一个主动作；选中这种组合时会收到上半身范围（骨架支持时）。
- 骨骼插值文案「修改选中键到下一键的过渡」与 `KeyframeTrack.sample` 一致：过渡用前一键的插值。整体键下拉「到下一关键帧的插值」与 `applyRootKeys` 使用 `prev.getInterpolation()` 一致。
- Dope Sheet 跳播放头走 `ActorAnimationKeyClock.seek`，位移时钟片段会落到投影后的场景时间。

## 应修改

### P1：点中演员轨道打开的是档案，轨道开关到不了采样

`getContextTarget` 在选择是演员轨道时直接返回注册表里的 `Actor`。`isTimelineTargetRenderedAsProject` 只对 `TimelineTrack` 且类型为 `ACTOR` 返回真，这个判断发生在替换之后，到不了。`PropertiesPanel.renderActorPanel` 没有调用方。

因此 `TimelineTrackPropertyAdapter` 里的轨道名、启用、锁定、创建片段按钮都不会出现在演员轨道上。那些创建按钮本会走 `ActorTrackClipAuthoringService`。同一适配器里的「复制轨道」「清空关键帧」仍是日志加 TODO，即便以后重新接到演员轨道，也不该原样露出来。

轨道头部的眼睛调用 `onToggleTrackVisible`，只翻转 `TimelineTrack.visible` 并更换图标。演员片段绘制不读 `visible`。预览停用读的是 `isMuted()`（`ActorRuntimeController`）。`ToggleTrackMuteCommand` 存在，时间线菜单里对它的 import 是注释。演员轨道上没有一条能让预览停下来的静音控制。

头部的锁调用 `onToggleTrackLock`，直接 `setLocked`，不进命令历史。编辑器各处确实会尊重锁定，但这次点击不能撤销。

建议：选中演员轨道时显示轨道页，至少包含名称、静音、锁定。静音必须写成采样使用的 `muted`。眼睛若继续存在，文案要说明它是否影响预览；以当前代码，它不影响。锁定和静音都应进撤销。身份档案留给列表和「查看演员」。

定位：`PropertyContextService.getContextTarget`、`isTimelineTargetRenderedAsProject`；`PropertiesPanel.doRender`；`TimelinePanel.onToggleTrackVisible`、`onToggleTrackLock`；`TimelineTrackRenderer` 眼睛图标；`ActorRuntimeController` 对 `isMuted()` 的判断；`TimelineTrackPropertyAdapter`。

### P1：同一次“选中演员”会打开两套面板

列表点击把 `actorInspection` 设上之后，属性面板在工具上下文之前返回，姿态工具页被盖住，工具本身仍开着。世界点击走 `selectWholeActor`，强制切回选择工具并清掉骨骼选择，于是看到身份档案。骨骼点击走 `selectBone`，强制切到姿态工具。

身份档案 `renderSelectedActorEditor` 在一页里连续放了：名称和类型、自定义骨架、聚焦/放置/删除、姿态图库、动作笔刷、分组、风格、皮肤、实时变换、占用、运行时诊断。姿态工具页再画图库，变换工具页再画实时变换。片段检查器的 `ActorClipInspectorGesture.begin` 每次又画一遍运行时诊断。

建议把档案收成身份卡：名称、类型、外观、分组、放置和删除。姿态图库、骨骼关键帧和 Dope Sheet 只留在姿态工具。实时变换只留在变换工具，或留在档案里的一个默认收起的小节，不要两处都默认展开。诊断留在片段页或场景诊断标签，档案上保留一条可跳转的状态。

定位：`ActorSelectionHub.selectActor`、`selectWholeActor`、`selectBone`；`ActorProjectPropertyAdapter.renderProperties`、`renderSelectedActorEditor`、`selectActor`；`EditorToolPropertyAdapter.renderActorToolProperties`、`renderAnimationAuthoring`；`ActorClipInspectorGesture.begin`。

### P1：默认布局里没有演员列表

`ActorsPanel` 默认隐藏。属性面板在没有选择时只提示去选择，不提供搜索、筛选、新建演员或新建分组。新建演员的弹窗挂在浏览器那条 `ACTOR_PROJECT` 路径上。

用户要先打开一个默认关闭的窗口，才能看到名单。选中之后，属性面板又变成上面那份长档案，名单消失。

建议：默认布局打开演员窗口，或在属性面板空状态下给出同一份名单和新建入口。名单和档案分成上下或左右，点一行只更新档案，不把名单卸掉。

定位：`ActorsPanel` 构造里的 `setVisible(false)`；`PropertiesPanel.renderProjectPanel`；`ActorProjectPropertyAdapter.renderProperties` 里仅 `ACTOR_PROJECT` 才画列表。

### P1：时间线骨骼行松手后，播放头不按菱形所在的时钟跳

骨骼行上的菱形和拖动预览用 `ActorAnimationKeyClock.projection`。位移用途的片段走 `AnimationEventClock`，同一资产时间可以对应多个场景时间，也可以不落在 `起点 + 资产时间 / 速度` 上。

松手时若发生了移动，播放头被设成：

`clip.getStartTime() + target / speed`

`importSelection` 里写入 `KeyHit.time` 的也是这个匀速式。Dope Sheet 的 `seekToKey` 用的是投影时钟，会在片段内挑离当前播放头最近的一次出现。

匀速片段上两者接近。位移时钟、循环或来回播放时，菱形在一处，松手后播放头到另一处。悬停提示用的是投影后的场景时间，和松手结果也不一致。

建议：时间线松手、选中导入后的跳转都改走 `ActorAnimationKeyClock.seek`，与 Dope Sheet 和菱形共用一个结果。

定位：`ActorBoneTimelineRows` 的 `importSelection`（约第 61 行）和拖动释放（约第 348 行）；`renderKeys` 里的 `clock.times`；`ActorAnimationDopeSheet.seekToKey`。

### P1：收起时间线会丢掉属性面板里的姿态草稿

`TimelinePanel.onContentUnavailable`、`dispose`、`clearWorkspaceEditingState`、`reloadForCurrentWorld` 都调用 `ActorAnimationEditingLifecycle.cancelTransientWork()`。`setVisible(false)` 会进 `dispose`。

`PropertiesPanel.onContentUnavailable` 明确不取消，注释写着共享草稿仍由时间线检查器使用。姿态编辑的主界面已经在属性面板的姿态工具里，Dope Sheet 也在那里。时间线里那块会在折叠时取消草稿的 `ActorTimelineAnimationPanel` 没有调用方，取消却仍然挂在整个时间线面板的生命周期上。

收起或停绘时间线时，属性面板上尚未提交的骨骼草稿、数值草稿会被清掉。

建议：取消草稿只跟编辑目标变化、切换工具、关闭工程或用户放弃绑定。面板被挡住或折叠时保留草稿。时间线面板若只是不可见，不要调用全局 `cancelTransientWork`。

定位：`TimelinePanel` 上述四个入口；`PropertiesPanel.onContentUnavailable`；`ActorAnimationEditingLifecycle.cancelTransientWork`。

### P2：出场片段一页承担了协调说明、两套时间和两层预设

`EntitySpawnClipPropertyAdapter` 的顺序是：默认展开的协调面板、范围文字、结束时间、时长、关键帧存在时禁用的位移旋转缩放、可见性、主预设、第二预设、混合、独立动作副本、整体关键帧。

协调面板在播放头位于片段外，或其他未静音出生片段才是当前生效片段时，写一句未生效然后返回。字段仍画在下面，只是被这段说明顶下去。结束时间和时长改的是同一个终点。

右键「出生」时长是 1 秒（变换、动画、状态、注视、关系是 2 秒，动作为 0.5 秒）。`ActorTrack.addDefaultSpawnClip` 的窗口是 5 秒。放置路径又是另一套时长。用户从菜单和从放置得到的可编辑区间不一致。

第二预设的两段说明（混合顺序、全权重覆盖限制）直接铺在出生页上，适合做悬停或一次折叠里的说明，不适合作为每次选中出生片段的正文。

建议：出生页只保留一个时间区间（起点、终点或起点、时长，留一组）、变换、可见性和预设。协调结果收成一行状态，展开后再列各层。右键新建与放置使用同一套默认时长，并在菜单项上写出来。

定位：`EntitySpawnClipPropertyAdapter`；`ActorCoordinationPanel.render`；`TimelineContextMenuFactory` 的 `ACTOR` 分支；`ActorTrack.addDefaultSpawnClip`；`ActorSpawnPresetPropertyUI`。

### P2：返回和拖动 Gizmo 时，三类检查器行为不一致

整体键的「返回所属片段」会离开检查并选中该片段。骨骼键的「返回所属片段」只把焦点设为假，选择对象不变，下一帧才回到原来的档案或片段页。

拖动演员 Gizmo 或骨骼 Gizmo 时，`ActorClipInspectorGesture.begin` 返回 `null`。出生、变换等检查器因此整页空白。整体键和骨骼键检查器在同一情况下保留控件并标为只读。

建议：两个「返回」都回到所属片段并保持键的选中。拖动 Gizmo 时片段页与键页一样保持只读显示。

定位：`ActorRootKeyPropertyUI` 返回按钮；`ActorKeySelectionPropertyUI` 返回按钮；`ActorClipInspectorGesture.begin` 里 `competing` 分支。

### P2：硬编码中文和类名夹在已国际化的控件之间

已走语言文件的区块和直接写死的句子叠在同一页。当前源码里至少包括：

- 姿态工具：「关键帧动画」「快速姿态自动应用」「旋转 / 位移（支持的骨骼）/ 缩放（支持的骨骼）」「阶梯、线性、平滑、贝塞尔」「在当前时间创建语义动作片段」。骨架一行用 `rig.getClass().getSimpleName()`。
- 身份档案：「现有动画与目标类型不兼容……」「更换类型前请先暂停并完成当前草稿。」自定义骨架的「（未绑定）」和绑定成功句。
- 实时变换开头的「当前编辑：演员整体……」。
- 时间线骨骼行：「模型根（局部）」「位置 / 旋转 / 缩放（局部）」、记录关键帧的提示、通道名提示。
- 整体键和骨骼键检查器的标题、只读句、应用和删除按钮。
- 片段只读原因：「工程不可用」「播放中」「正在拖动播放头」「轨道已锁定」等。
- 动画片段下拉的「动画」「选择动作」及两句说明。
- 出生预设树里的说明和「不兼容」「缺失引用」。
- 分组名称为空时的「分组名称不能为空」。

英文语言包改这些句子不会生效。骨架类名对用户没有意义，应使用已有的骨架显示名。

建议：上述字符串进 `zh_cn.json` / `en_us.json`，和同页已经使用 `ActorPropertyAdapterI18n` 的控件对齐。

## 建议的页面职责

按现在的代码，比较稳的切分是：

1. 演员窗口：搜索、类型筛选、分组、新建、删除确认。默认可见。
2. 属性面板里的演员卡：名称、类型、外观、分组和放置。提供「到轨道」「到姿态工具」而不是把后两者的控件嵌进来。
3. 演员轨道页：名称、静音、锁定，以及与右键菜单一致的新建片段。选中轨道时打开这一页。
4. 片段页：该片段自己的时间、目标和混合。协调与诊断默认收起。
5. 姿态工具：图库、骨骼 Gizmo、资产、Dope Sheet、骨骼键数值。时间线子行只负责看见和点选关键帧，跳转与 Dope Sheet 共用 `ActorAnimationKeyClock`。
6. 变换工具：播放头上的整体位移、朝向、缩放和注视。路由占用位置时继续禁用对应轴。

`ActorTimelineAnimationPanel`、`renderActorPanel`、替换之后才判断的 `isTimelineTargetRenderedAsProject`，可以在收口时删掉或接到真正的入口，避免下一轮再按它们设计。

## 本轮不重复列出的旧结论

- 2026-11-02 审计里「关键帧没有检查器、片段只读时面板空白」已过时。检查器和只读保留都在；空白只发生在 Gizmo 拖动期间的片段页。
- 语义动作和局部姿态的创建按钮已经进创作服务，不再是绕过撤销的直接写入。
- 注视、独立动作副本、循环路线时长若只存在于那份审计的「未修复」名单里，本轮没有把它们重新当成界面缺陷。当前注视工具有目标片段说明和创建/取消。
- 隐藏离场「只在结束点生效」已与现文案和 `hasCompletedDespawn` 不符，不在本报告重复。
