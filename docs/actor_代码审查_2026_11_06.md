# 演员（Actor）代码审查

日期：2026-11-06。审查对象是当前工作区 `8af77ac8`（`fix(actor): 强化静态姿态不可绑定为动作的校验`），工作区干净。范围是演员身份、时间线片段、采样与运行时、群组编排、姿态/动作资产，以及对应的撤销和存档。本轮按当前源码重新阅读，不沿用旧审查里尚未在本棵树上核对过的结论。没有修改产品代码，没有启动 Minecraft，也没有在本轮重跑测试套件。

## 本轮核对后仍然成立的设计

这些路径已经按当前实现核对过，本报告不把它们再列为缺陷。

- 新演员放置和重新放置进入 `ActorPlacementEditing`，用一条 `StateChangeCommand` 提交；撤销会按演员身份和轨道归属回滚。
- 演员类型切换在执行、撤销和重做时都会检查暂停、注册表身份、骨架来源和已有动画兼容性。
- 实体动画片段上的 `AnimationEvent` 会写入时间线 DTO，并在读档时加回去。
- 静态姿态不能从预设绑定、用途切换和群组预设计划里再当成动作挂上。引用计数包含第二预设。
- 跟随队形复制的是同一条路线，成员用时间延迟错开；来源演员会被跳过。变速和端点转身时，间距是按平均速度换算的时间差，不是沿弧长锁死的距离。
- 姿态文案约定后续片段从前一个姿态过渡，采样也按这个规则混合，不要求前一个片段仍然覆盖当前时间。
- 动画资产库先把文件完整解析进临时列表，成功后才清空并替换。

## 当前问题

### P1：隐藏离场只在结束时间的一个采样点生效

离场片段能在属性里选“隐藏”或“移除”。采样先用 `findClipsAt` 收集 `start <= t <= end` 的片段，再在 `applyDespawnClip` 里要求 `t >= end`。两个条件叠在一起，隐藏只在播放头正好落在结束时间时把 `visibility` 写成 0。

移除模式另有 `ActorTrack.isPresentAt`：结束时间之后，只要对应的出生窗口还在，演员会保持未出场。隐藏模式没有对应的持续状态。出生片段若比离场更长，离开那一个端点后可见性回到出生片段的值，演员会重新出现。播放步进若跳过结束时间，隐藏一次都不会发生。

文案写的是“离场在片段结束附近生效：隐藏仅关闭可见性”。当前实现是“只命中结束时间，且不保持”。

定位：`src/main/java/com/director/timeline/playback/entity/EntityClipSampler.java` 的 `applyDespawnClip`，`src/main/java/com/director/timeline/model/entity/ActorTrack.java` 的 `findClipsAt` 与 `isPresentAt`，`src/main/resources/assets/director/lang/zh_cn.json` 的 `gui.director.actor.despawn_edit.hint`。

### P1：缩短片段后，越界的整体关键帧仍参与采样，重载后消失

`EntityClip.setTimeRange` 只在时长不变的平移里移动关键帧。左右拉伸或改短时长时，关键帧时间留在原处。`addKeyframe` 会拒绝落在 `[start, end]` 外的帧，但已经在列表里的帧不会被删掉。

`EntityClipSampler.applyRootKeys` 的前后帧查找不要求关键帧落在片段内，所以这些帧继续插值，时间线上也能画出来。保存会把它们写进文件。读档再次调用 `addKeyframe`，越界帧被静默丢掉。同一次工程在重载前后的采样结果会变。

定位：`src/main/java/com/director/timeline/model/entity/EntityClip.java` 的 `setTimeRange`、`addKeyframe`；`src/main/java/com/director/timeline/playback/entity/EntityClipSampler.java` 的 `applyRootKeys`、`findPrevKeyframe`；`src/main/java/com/director/timeline/persistence/TimelineModelPersistence.java` 读关键帧处对 `clip.addKeyframe` 的调用。

### P1：演员列表被清空时，保存被当成成功，旧档仍留在磁盘

`ActorRegistry.isEmpty()` 只看演员表，不看群组。`ActorRegistryManager.persistNow` 在注册表为 `null` 或 `isEmpty()` 时直接返回 `true`，不写文件，也不删除旧文件。`TimelineModel.save()` 把这个返回值当成演员数据已经落盘。

因此删除最后一个演员时，`ActorDeletionService` 会调用保存，时间线里的轨道可以写掉，`actor_registry.json` 仍是删除前的内容。下次打开世界，演员和当时的群组成员会一起回来。只剩群组、没有演员时，群组修改同样不会写出去。

定位：`src/main/java/com/director/actor/ActorRegistry.java` 的 `isEmpty`，`src/main/java/com/director/actor/ActorRegistryManager.java` 的 `persistNow`，`src/main/java/com/director/timeline/model/TimelineModel.java` 的 `save`，`src/main/java/com/director/ui/actor/ActorDeletionService.java`。

### P1：路径、自定义骨架和自定义模型在解析完成前就清空库

`ActorPathPersistence.loadFromFile` 一进来就 `library.clear()`。某条路径的 id 不是合法 UUID，或路点缺少 `x`/`y`/`z` 时，异常跳出循环，库保持空白。随后任意一次 `ActorPathLibraryManager.save()` 都会把空的 `actor_paths.json` 写回去。

自定义骨架和自定义模型先检查 schema，然后清空库，再逐条 `register`。后面某一条读失败时，前面的条目已经进库，后面的条目丢失，异常被 `loadFromWorld` 吃掉。下一次 `TimelineModel.save()` 会把这个残缺库写回原文件。

动画资产库是先解析到临时列表、确认 id 不重复，再清空并注册。路径、骨架和模型还没有这条边界。

定位：`src/main/java/com/director/actor/path/persistence/ActorPathPersistence.java` 的 `loadFromFile`、`deserializePath`；`src/main/java/com/director/actor/rig/skeleton/CustomRigPersistence.java` 的 `load`；`src/main/java/com/director/actor/model/CustomModelPersistence.java` 的 `load`；对照 `src/main/java/com/director/actor/animation/asset/AnimationAssetPersistence.java` 的 `replaceFromJson`。

### P2：片段和整体关键帧的 id 写进文件后，读档会另发新 id

`entityClipToDTO` 会写 `cdto.id` 和关键帧 id。`getEntityClip` 只用名称和时间构造片段，构造函数内部 `UUID.randomUUID()`。关键帧则是 `new EntityClipKeyframe(kfdto.time)`，不使用 `kfdto.id`。

同一次会话里 id 稳定。重载后再保存，文件里的片段 id 和关键帧 id 会整批更换。当前诊断跳转使用的是会话内对象，这条问题还不会单独弄丢跳转；它会让时间线文件无法按 id 往返，也会让以后任何存在文件外的片段引用在重载后对不上。

定位：`src/main/java/com/director/timeline/persistence/TimelineModelPersistence.java` 的 `entityClipToDTO`、`entityClipFromDTO`、`getEntityClip`。

### P2：非法的肢体弯曲模式会丢掉整名演员

读演员时，未知的 `playerModel` 包在自己的 try 里，失败后保留默认外观。`limbBendMode` 和 `ActorType` 的 `valueOf` 在演员级 try 里，没有单独兜底。文件里只要这个字段拼错，整名演员被跳过，日志只有“加载 Actor 失败，跳过”。下次成功保存会把这名演员从注册表文件里抹掉。

定位：`src/main/java/com/director/actor/persistence/ActorRegistryPersistence.java` 的 `loadFromJson`。

### P2：重叠的状态片段会整组覆盖，而不是按字段叠加

`EntityStateClip` 的类注释写“可叠加”，例如用一条长片段维持发光。`applyState` 对最后一条未静音片段一次性写下潜行、冲刺、发光、无敌和可见性。后开始的短片段若把发光留在默认 `false`，会把仍在覆盖时间内的长片段发光清掉。潜行、冲刺和无敌目前仍不进预览；发光和可见性会进采样结果。

定位：`src/main/java/com/director/timeline/model/entity/EntityStateClip.java` 的类注释，`EntityClipSampler.applyState`。

### P2：同一开始时间的片段，赢家取决于片段类型

片段按开始时间再按 id 排序。动画、变换、状态、出生、离场在开始时间相同或更晚时替换当前赢家，同一时刻是较大的 id 生效。动作、姿态、路线、关系用的是严格大于，同一时刻是较小的 id 生效。两条同时开始的姿态里，id 较大的那条既不是当前姿态，也不会成为“前一个姿态”，因为前一个要求开始时间更早。

定位：`EntityClipSampler` 的 `applyAnimation` 与 `applyActorPose`。同文件里的变换、状态、路线分支使用各自的比较。

### P2：群组改出生位置时选中的出生片段，和采样使用的不是同一条

采样在重叠的未静音出生片段里取排序后的最后一条。`ActorGroupTimelineCommandService.findSpawnClipAt` 返回 `findClipsAt` 的第一条未静音出生片段，也就是开始更早的那条。属性会话只在用户改出生时间时拒绝重叠；读档和其他 `addClip` 路径仍可以留下重叠。此时群组放置、自由队形偏移和“从播放头复制路线”改的是较早的出生片段，画面上的位置来自较晚的那条。

定位：`EntityClipSampler` 里 `spawnClips.getLast()`，`src/main/java/com/director/ui/actor/group/ActorGroupTimelineCommandService.java` 的 `findSpawnClipAt`。

### P2：第二动作预设可以和第一预设绑成同一个全覆盖层

第二预设会进采样，并在姿态求解里叠在第一预设之上。新建绑定时 `ActorPresetBinding.select` 使用 `PoseBlendSettings.DEFAULT`，模式是 OVERRIDE、权重是 1。提交出生片段时会拒绝静态姿态，也会拒绝和第二层手工动画使用同一个 id，但不会拒绝第一预设和第二预设使用同一个动作。两个全骨骼覆盖层叠在一起时，第二层把第一层的已写通道盖住，第一预设看起来没有生效。

读档的 `readSpawnPreset` 不跑这套校验。文件里已经写成静态姿态的预设仍会播放。之后只要再提交这条出生片段，`requireAction` 会拒绝整次修改，需要先把该预设清掉，才能改位置或时间。

定位：`src/main/java/com/director/timeline/playback/entity/EntityClipSampler.java` 写入 `secondaryPresetAnimation` 处，`src/main/java/com/director/actor/runtime/ActorPoseEvaluator.java` 的第二层 `applyLayer`，`src/main/java/com/director/ui/actor/edit/ActorClipPropertyEditSession.java` 的 `validateBehavior`，`src/main/java/com/director/timeline/model/entity/ActorPresetBinding.java` 的 `select`。

### P2：播放头镜像只交换旋转，选中键镜像还会处理位移

`ActorAnimationAuthoringService.mirror` 给播放头镜像使用。它只为每块骨骼写入镜像后的旋转，位移和缩放通道留在原来的骨骼上。`mirrorSelection` 会把位移相对静息姿势的 X 取反，再写到对侧骨骼的静息位移上，缩放原样复制。

左右不对称的位移关键帧在“镜像播放头姿态”之后仍留在原侧，和“镜像所选键”的结果不同。两条路径都只处理人形拓扑。

定位：`src/main/java/com/director/ui/actor/pose/ActorAnimationAuthoringService.java` 的 `mirror` 与 `mirrorSelection`。

### P2：整体关键帧和骨骼关键帧的插值归属相反

骨骼通道用前一个关键帧的插值：STEP 保持前一个值，BEZIER 用前一个关键帧上的手柄。整体关键帧用后一个关键帧的插值，STEP 和 SMOOTH 都挂在即将到达的那一帧上。两套编辑器如果都把“这个关键帧的插值”理解成离开该帧之后的曲线，整体轨道会作用到它前面的那一段。

定位：`src/main/java/com/director/actor/animation/asset/KeyframeTrack.java` 的 `sample`，`EntityClipSampler.applyRootKeys`。

## 本轮看过、没有另列为缺陷的新逻辑

- 贝塞尔缓动把两个控制点限制在 `[0, 1]`，用 X 分量二分再取 Y。手柄拖拽在提交前就算出了新的 `BezierEase`，取消手势不会丢掉这次计算结果。
- 动画事件拖拽按场景时间反解相位，再写回同一条事件。循环事件的各次出现会一起移动，界面有这句话。事件列表的相等判断包含时间、时机和动作。
- 距离时钟的累计路程在循环和往返里继续增加，事件投影按片段边界切开后再要求单调。本轮没有看到往返路程把事件段整段丢掉的路径。
- 群组预设计划会拒绝静态姿态、骨架不兼容、以及和已有预设或动画片段重叠的成员，并给出跳过原因。
- 随机延迟使用群组上保存的种子；同一种子重复计算得到同一组延迟。

## 建议的验证

修复时建议按下面的场景补回归，再用客户端看一次画面。本轮没有跑这些测试。

1. 出生 0–10 秒，隐藏离场 2–4 秒。比较 `t = 4` 与 `t = 4.05` 的可见性，并让播放跨过 4 秒。
2. 整体关键帧在 1 秒和 8 秒，把片段改成 0–5 秒。比较改完当下和保存再加载之后的采样。
3. 删除世界上最后一个演员并保存，重新加载注册表，确认文件里不再有该演员。再保留一个空群组做同样的保存。
4. 路径文件里放一条合法路径和一条非法 id，加载后保存，确认合法路径还在。骨架和模型用“前几条合法、后一条缺字段”做同样的检查。
5. 两条出生片段重叠时，群组放置改动的那条应与当前采样使用的那条相同。
6. 第一预设和第二预设选同一个动作，确认界面说明第二层的覆盖范围，或拒绝这种绑定。
7. 带左右位移差的播放头镜像，结果应和对侧选中键镜像一致。
