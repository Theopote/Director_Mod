# 演员属性 UI 全面盘点

审查范围为当前仓库内可发现的演员属性入口及其依赖的编辑服务；这是代码与交互逻辑审查，不是 Minecraft 内截图、分辨率、停靠和鼠标交互验收。具体缺陷调用链另见 actor_property_panel_audit_2026_11_02.md。

## 新增问题

### U17：自定义模型 UV 编辑会丢失未提交草稿，并可能覆盖其他面的 UV，P1

CustomModelCuboidPropertyUI 为全部 cuboid 共用静态 textureId、uv0–uv3 和单个 activeCuboidIndex。每帧遍历所有展开节点并调用 syncDraft；当两个节点同时展开时，依次切换草稿，下一帧又重新初始化，前一个节点未应用的输入会丢失。

另外 primaryUv 只读首个有值的面，applyEdit 使用 CuboidFaceUvs.uniform 将它写回全部面。因此仅想修改贴图 ID，点击应用也会将原先六面各自的 UV 压成一套。应按模型身份和 cuboid 保存草稿，分别编辑贴图和逐面 UV；“应用全部面”必须显式选择。

### U18：动作风格与自定义骨架/模型绑定绕过统一编辑保护，P1

RigProfileStylePropertyUI.slider 反射修改原 style 字段，由上层 markDirty，没有手势命令、撤销或统一只读状态。EditorToolPropertyAdapter 和演员详情都能调用它。

ActorProjectPropertyAdapter.renderCustomActorAssets 的骨架及外观下拉直接 setCustomRigId/setCustomModelId，未使用外观命令；该区域没有播放/拖动期间的禁用。绑定骨架会改变编辑能力和动画兼容性，应预检现有引用、统一取消旧上下文并提供撤销。不能因为其他外观项已迁移命令，就认为整个外观区域都有同样保护。

### U19：独立动画片段引用缺少可用的选择与验证流程，P1

EntityAnimationClipPropertyAdapter 暴露“内建/自定义”和原始动画 ID 文本。ActorClipPropertyEditSession.Animation.validate 只检查 ID 非空和速度范围，没有检查资产存在或与当前演员骨架兼容；validateBehavior 也没有 Animation 分支。输入拼错 ID 可保存，之后才在其他诊断或混合区域出现引用不存在提示。

应复用兼容动画目录，显示名称、来源、骨架和不可用原因；旧缺失引用保留并允许修复，但新增/更改绑定要检查。不能静默自动更换或删除旧缺失引用。

隔离测试已确认：ActorClipPropertyEditSession 可以把引用从一个缺失 ID 改为另一个不存在的 ID，commit 返回成功；撤销能恢复。因此问题是提交校验缺失，不是撤销失效。探针位于忽略目录 build/property-audit-src，运行方法 animationInspectorCurrentlyAcceptsMissingReference；该测试验证缺陷存在，并不表示已修复。

### U20：动画事件缺少可查看、可编辑的属性入口，P2

AnimationEvent 已有片段/动画源两种时钟并能持久化，但演员 UI 未发现针对它的时间、动作、参数、时钟或循环触发编辑器。独立 EntityActionClip 道具事件表单不是同一数据入口。应至少能列出已有事件，显示时钟和实际触发语义，再提供带撤销的编辑；不能让导入事件只能通过文件修改。

### U21：高密度布局、术语和只读原因需要统一，P2

若干适配器同时由 PropertiesPanel 和自身重复绘制标题；多个界面直接硬编码中文，而其他界面使用翻译键。姿态、语义动作、动画引用、手工层、资产、Root 的称谓没有统一对象层级。常见不可用提示把播放、锁定、静音、缺失引用和骨架不兼容合并为同一句，用户无法知道下一步。

建议固定对象头部和上下文导航，统一使用具体只读原因；高级资产 ID 和诊断折叠；键属性优先显示所选键而非所属片段参数。窄面板、长演员名、多语言溢出、键盘焦点和滚动区域仍需客户端专项验收。

## 保留及下一步

应保留已有的路径通道保护、距离驱动重定时限制、共享资产影响提示、原子粘贴、命令撤销和草稿有效性校验。本次未将正常的只读限制或未实现的禁用控件算作功能错误。

优先级：先修复数据语义与破坏性副作用（当前值/端点、UV、引用绑定校验），再统一选择检查上下文和只读显示，随后处理跨面板草稿生命周期与距离时钟定位，最后整理布局、文案和事件编辑器。
