# 天气轨道规则与验收

## 天气采样与生命周期

天气轨道采用轨道级关键帧，激活一条轨道进行采样；首帧之前、末帧之后保持端点值。有关键帧才启用天气覆盖。空轨道、删除最后一帧、取消绑定或关闭编辑器会清除天空、闪白和本模块拥有的粒子。关键帧的删除、批量删除、撤销、重做通知会重建采样缓存。

阶梯插值保持左侧参数至下一关键帧的精确时间；线性和平滑插值保持原定义。风向按最短角度过渡。非有限参数采用中性值，风向用取模归一化，避免异常存档数值造成死循环。云速范围为 0–4，闪电频率范围为 0–20 次/秒。

天气覆盖只改变渲染读取，不再改写客户端原版雨量、雷量或下雨标记，也不拦截服务端天气更新。关闭覆盖后，显示持续更新的原版天气；编辑器开启且没有有效天气覆盖时，仍按既有导演模式规则隐藏随机降水。

## 时间线驱动的效果

- 闪电事件按时间线上的固定 20Hz 时间格及稳定种子计算，闪白直接由事件年龄采样。重复渲染、跳转和导出等待不会增加事件次数。
- 雷声和客户端闪电实体仅在连续向前播放时触发；跳转、静态预览和导出不重放这些副作用。视频音轨仍仅包含音频轨道，不会自动录制实时游戏雷声。
- 云层位移积分云速和风的影响，关键帧处不会因为“累计时间乘当前速度”而跳变。预览使用当前天气样本的时间。
- 雨雪、地面水花及特殊天气共用独立粒子池，按时间线重建最近的短时粒子窗口；总活跃数量最多 12,000。位置、风向运动和粒子初始化种子由时间线确定，暂停和抓帧重试不重复发射。
- 粒子在相机与世界采样之后更新。跳转会重新匹配粒子集合；关闭覆盖只移除天气模块拥有的粒子，不清空其他粒子。
- 为保持数量与性能可控，满强度雪的发射密度较旧版本降低。粒子围绕摄像机所在的 16 格空间单元生成，在相机跨单元时重新建立可见粒子池。

雾仍按原有设计禁用，本次没有新增雾渲染或积水反射。沿用 Minecraft 粒子材质和粒子管理器，纹理动画、其他模组与游戏事件仍可能影响最终画面；本次不保证整个 Minecraft 世界逐像素的确定性。

## 验收步骤

1. 0 秒晴天、10 秒雨天设置阶梯，确认 10 秒才切换；检查线性、平滑和 350°→10° 风向过渡。
2. 删除天气关键帧、批量删除、撤销和重做；删除最后一帧和切换空轨道，确认不再保持旧天气。
3. 在雪天和闪电时关闭覆盖、关闭编辑器或切换项目，确认没有旧雪花发射和闪白残留。
4. 在原版雨天打开再关闭编辑器，确认原版天气恢复；编辑期间收到服务端天气更新，也应在关闭后体现。
5. 对同一时刻反复跳转、暂停及导出，检查闪白、云位置、天气粒子分布稳定。包含镜头切换的序列应在新镜头周围生成天气粒子。
6. 满强度雨夹雪、暴雪和特殊天气叠加，确认天气粒子池有上限，卡顿或大幅跳转后不会按墙钟间隔集中生成数万粒子。

自动测试验证采样、缓存、清理及效果数据；实际视觉、粒子密度和视频导出仍需游戏内验收。
