## 结论与边界

当前 Actor 已有相当完整的单角色动画基础：整体及骨骼关键帧、预设与手工层混合、路径距离时钟、注视与关系、道具事件、资产导入导出、撤销及运行诊断。下一步最有价值的工作，是让这些能力形成可预测的制作流程，并补齐群体动画的编排与修改能力。

群组目前本质上是“成员集合 + 批量生成独立片段的参数”，不是可以持续调整的群体表演对象。它适合简单批处理，但制作转弯队列、反复调整的群舞、带个体差异的人群时，用户很快会回到逐个演员、逐段片段编辑。

本轮是跨模块代码和行为审查，没有启动 Minecraft 进行视觉验收。不能据此断言实际画面存在滑步、穿模、面板溢出或性能不达标；这些列为实机验收事项。本轮没有修改产品代码。旧审查中已修复的事项不再重复列为当前缺陷。

## 当前问题：按影响排序

### E01 / P1：群组放置成功，并不代表当前画面中的演员被移动

**证据：隔离测试确认。** `ActorGroupTimelineCommandService.placeGroup` 只改变或新建 Spawn 的位置；`previewPlacement` 只检查成员和轨道，没有检查 Transform、Route、Relation 对位置的控制。

复现：Spawn 为 0–10 秒，另有 0–10 秒的 Transform 将 X 固定为 10。在第 2 秒将群组放到 X=100，服务返回成功，Spawn.X 成为 100，但同一时刻实际采样仍为 X=10。这会产生“按钮没用”的直观体验，并且改动会影响其他使用 Spawn 位置的时间段。

单演员 `ActorPlacementEditing.relocate` 已具备路径/关系检查，并通过整体键服务写当前帧；群组没有沿用该语义。

建议：批量操作先逐成员解析实际写入目标，明确区分“移动当前帧”“整体平移表演”“修改入场位置”。生成可审阅的修改集合，再一次性提交。验收必须比较提交前后同一播放头的采样结果，而不只检查字段和返回数量。

定位：[群组放置](../src/main/java/com/director/ui/actor/group/ActorGroupTimelineCommandService.java#L199)、[单演员重放置](../src/main/java/com/director/ui/actor/placement/ActorPlacementEditing.java#L60)。

### E02 / P1：群组操作会静默选择演员的第一条根轨道

**证据：隔离测试确认。** 群组成员检查、创建动作、复制路线和放置反复调用 `TimelineModel.findActorTrackByActorId`。该函数只遍历根轨道，并返回第一个匹配项。

复现：同一演员绑定 A、B 两条轨道，明确选择 B，创建群组动作，实际写入 A。子轨道绑定还可能被判定为无轨道。现有单演员资产编辑使用 `getAllTracks` 和显式选择/歧义拒绝，规则不一致。

建议：群组预览列出“成员 → 目标轨道”，歧义成员要求指定或跳过；不要依赖轨道排列顺序。一次命令内固定目标集合，执行及撤销校验目标身份。

定位：[成员检查](../src/main/java/com/director/ui/actor/group/ActorGroupTimelineCommandService.java#L98)、[根轨道查找](../src/main/java/com/director/timeline/model/TimelineModel.java#L799)。

### E03 / P1：已有演员的鼠标放置仍使用准星命中，与新增放置不一致

**证据：代码调用链；鼠标偏移需实机验收。** 列表“放置”通过 `ActorSelectionHub.beginPlace` 进入 `ActorPickController`。其 `resolvePlacementHit` 直接返回 `client.crosshairTarget` 中的 BlockHitResult；没有确认命中类型为 BLOCK。后续虽然计算 ImGui 鼠标射线，但直接返回 null，没有用它完成检测。

新增演员的 `ActorPlacementController.resolvePlacementHit` 则优先使用当前/ImGui 射线并检查命中类型。鼠标离开屏幕中心时，两种“放置”可能落在不同位置；MISS 类型的 BlockHitResult 也可能被旧分支当成有效位置。

建议：两个入口共用 ActorViewportRay 或统一放置命中解析，预览与提交使用相同结果；无地面时明确不可放置。验收覆盖自由鼠标、不同镜头方向、天空、UI 遮挡和外置窗口。

定位：[旧放置命中](../src/main/java/com/director/ui/actor/pick/ActorPickController.java#L257)、[新增放置命中](../src/main/java/com/director/ui/actor/placement/ActorPlacementController.java#L208)。

### E04 / P1：演员类型切换仍绕过播放与草稿保护

**证据：播放状态下的类型切换已由隔离测试确认。** 演员详情的类型下拉主要检查动画兼容性；`ActorPropertyEditing.changeType` 没有检查播放、拖动、注册表身份和当前草稿。底层命令桥也不自动提供这些检查。

复现：没有动画引用的 PLAYER 在播放期间仍可切换为 COW。这里不声称一定发生崩溃，但它会在运行中替换 rig profile、重建预览，并且与自定义骨架绑定和风格编辑要求暂停的规则不同。

建议：采用与 `ActorAppearanceEditing` 一致的状态检查，预检动画及其他依赖，明确提示草稿处理方式；将兼容性检查放进服务，避免只在 UI 保护。不要把可安全进行的重命名与会更换骨架的类型修改一概处理。

定位：[类型 UI](../src/main/java/com/director/ui/properties/adapters/ActorProjectPropertyAdapter.java#L449)、[类型命令](../src/main/java/com/director/ui/actor/ActorPropertyEditing.java#L34)。

### E05 / P2：默认“自由”队形会让所有成员重叠

**证据：隔离测试确认。** 默认 FormationType 为 FREE，计算时每个成员都返回同一个 centerPosition。直接点击群组放置会让所有成员占据同一点；复制路径时也不会保留原有成员间相对位置。

“自由”容易被理解为保留当前自由摆放。建议定义为保留成员相对布局，或者改名为明确的“重合位置”，并为首次群组放置选择非重叠默认队形。不要默认悄悄重排已有站位。

定位：[FREE 队形](../src/main/java/com/director/actor/group/ActorGroupController.java#L40)。

### E06 / P2：队形位置与朝向契约不一致

**证据：两个隔离测试确认。**

- GRID：4 人、间距 2、锚点 (0,64,0)，成员平均中心为 (-1,64,1)，不是锚点。LINE 却围绕锚点居中。这属于锚点约定不一致，不应在没有产品定义时简单认定必须采用中心。
- CIRCLE：队形计算产生不同成员 yaw，放置服务却全部写入相同相机 yaw，丢弃计算值。目前并没有可供用户选择的“面向中心/朝外/统一朝向”规则。

建议：显式定义中心、领队或首成员锚点；队形预览显示锚点及朝向箭头，提交沿用同一结果。

定位：[GRID/CIRCLE](../src/main/java/com/director/actor/group/ActorGroupController.java#L54)、[统一覆盖 yaw](../src/main/java/com/director/ui/actor/group/ActorGroupTimelineCommandService.java#L226)。

### E07 / P2：“跟随领队”目前是路线平移副本

**证据：隔离测试确认。** `copyRouteClip` 将同一个世界空间偏移加到每个路点，没有随转弯更新队形，也没有沿领队历史路径采样。

例：领队路线 (0,0)→(0,10)→(10,10)，跟随者间距 2，副本为 (0,-2)→(0,8)→(10,8)。跟随者在另一条折线上行走，不会沿领队的路线经过拐角。

这是群组路线复制的限制，不意味着独立 Relation/FOLLOW 功能不存在。建议区分“平行路线编队”和“沿领队轨迹跟随”；后者可以基于路径弧长或历史时间偏移实现，并定义队首、延迟和拐弯行为。当前名称至少需要说明限制。

定位：[复制路点](../src/main/java/com/director/ui/actor/group/ActorGroupTimelineCommandService.java#L290)。

### E08 / P2：群组路线复制没有明确到具体片段

**证据：隔离测试及 UI 调用链。** UI 选择源演员，但没有源路线选择器。服务自动选择播放头之前起点最晚的路线；如果播放头在所有路线之前，则取整个轨道起点最晚的一条。

复现：源演员有 5–10 秒和 20–25 秒路线，在第 0 秒复制，实际复制 20–25 秒路线。预览只展示可操作人数和跳过原因，不展示这段路线的名称、时段及生成后的范围。按钮/提示还沿用“选中演员”文案，与专用源演员下拉不完全一致。

建议：显式选择路线，显示源轨道、片段名、时间范围、独立副本/链接方式；选项提供保留原时间或从播放头开始。未明确来源时不自动猜最晚未来路线。

定位：[来源 UI](../src/main/java/com/director/ui/properties/adapters/ActorProjectPropertyAdapter.java#L323)、[来源解析](../src/main/java/com/director/ui/actor/group/ActorGroupTimelineCommandService.java#L267)。

### E09 / P2：群组成员编辑流程不闭合，延迟顺序不可直观控制

**证据：界面和数据结构。** 群组详情可移除成员，却没有同区域的批量添加、搜索选择或顺序调整；添加主要在每个演员的“所属分组”复选框完成。成员由 LinkedHashSet 保存，加入顺序同时决定队形槽位和顺序延迟。

用户想让 C 第一个行动，需要理解隐藏的加入顺序，或者删除重加。人数多时成本尤其高。

建议：在群组详情提供成员表，支持批量添加、拖动排序、领队标记、预览起始时间和队形槽位。明确区分“成员排列”“空间队形”“动作触发顺序”，避免一个顺序隐式控制所有行为。

定位：[成员 UI](../src/main/java/com/director/ui/properties/adapters/ActorGroupPropertyAdapter.java#L110)、[演员加入分组](../src/main/java/com/director/ui/properties/adapters/ActorProjectPropertyAdapter.java#L792)。

### E10 / P2：群组参数修改不会更新已经生成的表演

**证据：数据模型和生成服务。** 群组不持有生成片段；生成的动作和路线不记录该批次所属群组。改变延迟/间距只影响之后的生成。路线副本不保留 sourcePathId，因此源路径修改不会自动传播。

这是现有独立副本设计的结果，不是持久化丢失。问题是用户缺少明确反馈，也没有“选中本批片段”“更新本批”“脱离群组控制”的入口。再次生成路线还可能因已有路线冲突而跳过成员。

建议：保留当前独立生成模式，并在创建前明确“生成后独立”；下一阶段增加批次 ID 和生成参数，支持预览差异后重新生成，以及保护个体手工修改。不要直接把所有群组成员都改成运行时强制约束。

定位：[群组模型](../src/main/java/com/director/actor/ActorGroup.java)、[批量生成](../src/main/java/com/director/ui/actor/group/ActorGroupTimelineCommandService.java)。

### E11 / P2：“在世界中聚焦”实际仅执行选择

**证据：按钮和调用链。** 按钮仅调用 `ActorSelectionHub.selectActor`，不计算演员包围盒或调整视角。演员在镜头外时，用户仍找不到它。

建议：提供真正的 Frame Selection，或把按钮改名为“选中演员”。定位只移动编辑视角，避免意外改动拍摄相机关键帧；演员当前不可见时显示原因及相关片段入口。

定位：[聚焦按钮](../src/main/java/com/director/ui/properties/adapters/ActorProjectPropertyAdapter.java#L506)。

### E12 / P2：改演员名会同时覆盖自定义轨道名称

**证据：当前实现及既有 renameUndoRestoresIndependentTrackNames 测试。** rename 对所有引用轨道统一 setName(after)，也改变 payload displayName。撤销可以恢复，因此不是不可恢复的数据丢失。

多个表演轨道原本叫“走进房间”“回头”等，改角色名后都变成相同演员名，会降低复杂时间线的可读性。

建议：只同步仍使用默认名称的轨道；自定义名称保持不变。界面分开显示“演员名”和“轨道名”，提供显式批量同步选项。

定位：[重命名](../src/main/java/com/director/ui/actor/ActorPropertyEditing.java#L12)。

## UI 结构判断与优化方案

### U01：信息按实现模块排列，尚未充分按制作任务组织

姿态工具同时容纳风格、姿态画廊、草稿、关键帧设置、资产库、骨骼属性、Dope Sheet、语义动作创建和局部覆盖。时间线还可渲染另一份骨骼属性和 Dope Sheet。功能能找到，但新用户需要先理解内部对象分类。

建议固定顶部对象信息：演员名 → 轨道/片段 → 当前编辑层；显示场景时间、必要时显示资产时间、写入范围和共享引用数。一级任务采用“移动 / 表演 / 互动 / 外观”，资产管理和诊断放次级区域。关键帧面板保持专门检查所选键，不回退为播放头采样值。

时间线优先负责时序、层关系和选键；属性区负责精确数值。允许展开时间线内骨骼编辑，但应使用紧凑模式或明确主编辑区，减少两份完整控件同时展开。

依据：EditorToolPropertyAdapter.renderActorToolProperties/renderAnimationAuthoring；ActorTimelineAnimationPanel。

### U02：路径功能已有衔接，但仍需统一“运动任务”摘要

路径库、Route 参数和世界几何工具各有职责，不能只靠合并面板解决。建议提供一个共同摘要：路径来源、当前运动控制者、区间、单次/循环、速度或时长驱动、朝向、步态、地形问题，以及进入几何编辑/返回 Route 的导航。

ONCE 由时长决定有效速度，循环使用速度；当前已有禁用与说明，应把这一区别放在主字段旁，减少用户把灰色速度理解为失效功能。

### U03：只读原因和操作反馈仍不够具体

已有大量保护值得保留，但部分界面把播放、锁定、静音、草稿等合并为一句提示。Route 只读分支也丢弃捕获异常的具体原因。群组操作结果主要写日志，界面预览数量不等于执行结果。

建议显示最直接阻塞原因和可操作入口，例如“轨道已锁定：解锁”“请先应用骨骼草稿”；操作后显示实际完成数量、失败成员、生成范围，并提供定位结果。不要用长期弹窗打断每次小操作。

### U04：术语、长表单及窄宽度需要专项整理

当前仍有中文硬编码、枚举名和英文参数混排；事件中的 slot/oldSlot/offsetX 等偏实现语义。部分适配器重复绘制标题，多个按钮 sameLine，演员列表还未做可见区域裁剪。

建议统一“演员、整体变换、骨骼动画、快速姿态、动作预设、语义动作、动画资产”的含义；把技术 ID 放高级区。事件按道具/挂点/偏移/投掷分组并给出单位。窄面板折行、长名称省略与 tooltip、键盘焦点须实机测，不能仅凭源码认定已溢出。

## 面向复杂角色/群体表演的功能缺口

以下是产品能力提升，不应全部作为当前 bug。

| 能力 | 当前边界 | 建议 |
| --- | --- | --- |
| 精细表演节奏 | 骨骼通道插值为 STEP/LINEAR/SMOOTH；不是带可编辑切线的曲线系统 | 在现有 Dope Sheet 基础上增加曲线/缓动控制、整段时间缩放；先定义旋转曲线语义 |
| 群体差异 | 随机策略主要随机启动延迟，seed 来自 group UUID | 暴露可保存 seed；增加速度、相位、强度及姿态变体范围，提供重抽和锁定个体 |
| 群组循环动作 | 创建动作 UI 固定传 loop=false，底层服务实际支持 loop 参数 | 暴露单次/循环和起始相位，明确与语义动作本身周期的区别 |
| 协同表演 | 有 FACE_TO_FACE/FOLLOW/CIRCLE_AROUND/RELATIVE_POSITION；不是完整双人动作配对编辑器 | 增加共同时间锚点、相对站位预览；递交物品等先做完整可验收模板 |
| 非人形角色 | 牛羊/村民没有独立骨骼关键帧绑定，仍可用已有过程动作 | 创建时提前展示能力；按需求扩展四足/村民 rig，避免用户做到一半才发现限制 |
| 动作和事件复用 | 独立 Animation 片段有事件编辑；AnimationAsset 导出只包含自身数据，事件属于片段 | 区分“导出骨骼动画”和“导出完整表演预设”；后者打包片段事件及依赖 |
| 自定义资产分享 | 动画导出保存 rigId，导入依赖目标环境已有该 rig；不包含完整模型、贴图和道具包 | 增加依赖清单、缺失说明；后续设计包含依赖的预设包 |
| 场景级排错 | 有单演员/片段运行诊断与 Spawn 层来源反馈 | 增加全场景演员问题列表，可按缺失资产、不可见、控制冲突筛选并定位 |
| 大规模编辑 | 群组预览在每帧重复查轨道和动作区间，演员列表逐项渲染 | 先测 10/50/100/300 人；按模型修订号缓存预览，虚拟化长列表。未测性能前不声称容量上限 |

## 实施顺序及验收

1. **先修写入与选择正确性：** E01、E02、E03、E04。验收“用户操作的目标、服务修改的目标、当前画面采样的目标”一致，撤销重做后仍一致。
2. **再完成群组基础工作流：** E05–E10。先把独立生成语义讲清楚，补成员管理、来源片段选择、站位/时序预览和生成结果定位；再实现关联批次更新。
3. **整理 UI：** 固定对象信息和作用范围，统一只读原因、术语、路径导航及骨骼编辑区；补聚焦和重命名细节。
4. **提升表现力：** 曲线编辑、群体变化、配对表演、非人形 rig 和预设包，逐项做闭合场景，不同时铺开半成品入口。

推荐实机验收场景：

- 一名演员：入场→沿弯路行走→停步转身→看向目标→挥手→离场，逐帧拖动和倒序检查。
- 两名演员：对视、跟随、交错动作与道具事件，改变时间后检查关系和事件。
- 十名演员：自由站位变网格、重新排序、波浪动作、弯路跟随、修改群组参数后更新同一批表演。
- 复杂工程：同演员多轨道、锁定/静音、共享资产、内嵌手工层、不同来源动作重叠，检查显式目标。
- 界面：窄属性面板、长名称、英文界面、停靠/收起/外置窗口、草稿期间切换选择。
- 保存重载、撤销重做、重复拖动播放头；导出自定义动画到缺少 rig 的工程，检查失败提示和原数据保留。
