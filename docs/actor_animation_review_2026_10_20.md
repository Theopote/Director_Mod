# 演员动画分层审查与实施记录

日期：2026-10-20。对照当前工作区、用户提供的 actor_fixes.patch、actor_pose_layer_stack.html、locomotion_phase_pipeline.html；补丁仅作为待核验建议，未整体应用。

## 结论与既有约定

采用“逐骨骼 × 逐通道 + 权重 + 明确层职责”的方向。AnimationAsset / BoneTrack 是动画数据，时间线关键帧是其编辑入口；已有 RigPose.authoredChannels 是合成基础。现有系统已经支持稀疏通道覆盖，不能把所有 last-wins 都归为全姿态覆盖。

保留已与用户确认的产品规则：

- 演员片段决定当前显示区间；删除片段/轨道后对应演员不继续留在世界中。不改成永久 Spawn 事件。
- 演员拾取路径后按路径几何运动，不自动投影地形。足接触不能反过来改变用户绘制的整体轨迹。
- 骨骼创作绑定原演员片段，不因为增加动作层而另建可见演员片段或轨道。
- 项目处于开发期，无旧文件兼容要求；统一数据时不额外设计长期兼容链。

## 对审查结论的校正

| 原建议/断言 | 当前核对结论 |
| --- | --- |
| 路径、运动和动作共写 actionLocalTime | 确认。场景默认值、Transform、Route 和显式语义动作都写入该字段，本轮拆分。 |
| 动画也共用 actionLocalTime | 不准确。动画已有独立 animationLocalTime，本轮保留。 |
| 非玩家快慢路径步频完全相同 | 不准确。原 time() 已乘 speed/reference；真正的问题是加减速时不能用瞬时速度乘时间替代路程积分，强度/走跑分类也影响频率。 |
| 所有骨架套用 playerTime 即可 | 不采用。四足公式为 (2.5 + intensity)，人形为 (2 + intensity)；本轮按各 profile 自身频率换算。 |
| 弧长相位保证绝不滑步 | 不成立。还取决于步幅校准、支撑相轨迹、局部/整体缩放、脚底接触和约束。相位同步只是必要基础。 |
| 临时 sampler 会在 UI 每帧执行世界事件 | 临时 sampleAt 的确会产出重复事件，但还要看调用方是否消费；不能把“产出事件”直接等同于“执行事件”。本轮查询入口不产出也不消费事件缓存。 |
| 用同一个常驻播放 sampler 做关系/历史时间查询 | 不采用。查询其他时刻可能消费/污染播放触发缓存；查询与事件派发职责必须分离。 |
| WeakHashMap<Track, Sampler> 可解决查询缓存生命周期 | 补丁的 sampler 强引用 track，形成 value 到 key 的回引用，弱 key 不保证释放。本轮没有引入该全局表。 |
| 默认 0.01 秒造成当前演员一动播放头就消失 | addDefaultSpawnClip() 确有极短区间，但当前没有生产调用；现行 UI 演员片段具有时长。不能据此改掉片段生命周期。 |
| EntityRenderOverride 无渲染消费者 | 确认当前仅发布/清理，作为旧链路后续清理；不把它与现行 clip 内根关键帧/骨骼关键帧混同。 |
| 更新只有 20Hz | 当前不成立。UIPlaybackBridge.tickFromRenderWorldHead 在 GameRenderer.renderWorld 之前按渲染帧推进；tick 方法名不代表游戏 tick。离线 TimelinePlaybackSampler 是独立入口，不足以证明实时同帧双驱动。 |
| RigPose.overlay 不应抛异常 | 核心层保留骨架一致性校验合理；应由层调度入口检查并报告不兼容层，不能直接吞掉所有异常。 |
| 路径结束或片段空隙应自动保持演员存活 | 与当前产品约定冲突，未采用。 |
| 层合成后所有约束无条件覆盖手工关键帧 | 不采用无条件覆盖；需定义可关闭的约束和受保护通道，编辑草稿仍需有最终可见反馈。 |

## 本轮已实现

- [x] 时钟拆分：routeLocalTime 只由路径写入，motionLocalTime 由自动运动来源写入，actionLocalTime 只由显式语义动作写入；animationLocalTime 保持独立。copy/lerp 同步支持新时钟。
- [x] EntityClipSampler.sampleSnapshot：用于 UI、关系、历史道具位置查询，不发 Action/AnimationEvent，不消费播放采样器的触发缓存。实时播放仍用自己的 sampleAt。
- [x] ActorRouteGait.phaseCycles 派生路径步态相位，不增加一个无人计算的可写 locomotionPhase 字段。ONCE 使用路程积分，LOOP/PING_PONG 使用累计行程，往返折返点不倒转步态相位。
- [x] 显式 WALK/RUN 在路径上也锁定路程相位；IDLE/DANCE 等动作与无路径动作仍用自己的时间，不强行套循环步态。
- [x] ActorRigProfile 提供名义步幅与实际步频换算。人形默认步幅 0.8 格/周期、四足 1.2 格/周期，作为待视觉校准的初值，非真实脚接触保证；保留现有整体前向缩放处理。
- [x] 曲线缓存记录插值模式和精确控制点快照，坐标编辑、插值切换或引用路径几何变化均失效；缓存值不反向引用 ActorRouteClip。路长、路径取点和步态路程复用同一曲线。
- [x] 注视草稿仅在注视求解时作为临时输入，不再改写 lastSample.lookAtPoint。
- [x] 历史道具位置查询使用临时 ActorRuntime，避免重置实时运行时的程序化动作状态。
- [x] pruneDeadTracks 使用同一次轨道快照和 identity set 判断归属，消除逐轨道 List.contains 的平方扫描；保留片段生命周期判定。
- [x] 没有程序化底层时仍执行 quickPose 回调，再叠加 authored 通道，不再丢弃回调。
- [x] 修正旧 ActorBoneDraftTransactionTest：首次创作应该绑定原 Spawn，不再断言生成独立 Animation 片段。

## 未在本轮完成的结构工作

1. PoseLayer：不可变的姿态输入、骨骼/通道掩码、OVERRIDE/ADDITIVE、权重、明确参考姿态。加法位移用参考差值，旋转用参考四元数差，缩放使用参考比例；不能直接叠加绑定姿态的绝对平移或缩放。
2. 层过渡：位置/缩放插值与四元数 slerp，淡入淡出由片段时间确定。根位移平滑不能依赖上一帧累积状态，必须支持任意 seek 和离线采样。
3. 统一编辑入口：动作引用、当前资产手工编辑、局部修正层要有明确区别，全部归属演员表演片段。ActorPoseClip 的区域式参数逐步由逐通道创作替代。
4. 数据链清理：审计旧 ActorTrackSampler / TimelineActorController / EntityRenderOverride 的调用与 UI 后，移除未生效链路及误导注释；不在仍有调用时直接删除。
5. 唯一实例归属：运行时与绑定入口统一处理同一 actorId 的多轨道歧义，避免道具/动画 Map 互相覆盖；不能简单取第一条轨道。
6. 缓存后续：本轮避免重复曲线重建，但仍逐控制点校验缓存、逐段查找距离，没有引入完整轨道样本缓存或所有关键帧索引。后续需结合编辑版本和触发语义设计。
7. 约束与性能：按通道处理足接触保护，补充速度曲线与步幅视觉校准；在清晰的姿态快照所有权基础上减少防御性复制。不能直接删掉复制暴露共享可变数组。
8. 清理残留 API：ActorRuntime.update、旧播放器 deltaTime 接口、默认极短 Spawn 便捷方法等另行确认调用后清理，不把删除字段混入相位修复。

## 验收重点

- 在同一路径的中途加入 WALK/RUN 动作片段，腿部周期不因动作片段起点而重置；改变动作强度不改变当前路程相位。
- 人形、四足分别测试一次/循环/往返路径、加减速、2 倍缩放、回拖与随机跳转。
- 手工头部旋转/手臂缩放只控制已创作通道，未创作腿部继续程序化运动。
- 反复打开属性、移动 Gizmo、查询关系或历史投掷位置，不额外产生事件，不吃掉下一次播放事件。
- 修改路径锚点、切换插值后，位置和相位使用更新后的曲线；路径整体不被地形修改。
- 删除/静音演员片段或越过显示区间后不留下预览演员。

自动化验证记录见同日实施进度；原生游戏步幅、脚底观感和性能仍需实际验收。


## 2026-10-21 姿态合成器基础已落地

- 新增 PoseLayer：捕获源姿态、参考姿态及骨骼掩码的独立快照；通道掩码与 authoredChannels 相交，权重限制到 0–1，非有限权重拒绝。OVERRIDE 层不额外创建参考姿态。
- 新增 RigPoseComposer：按调用方给定的低到高顺序，执行加权覆盖或参考姿态加法。覆盖采用局部位移/缩放 lerp、旋转 slerp；加法采用位移差、参考旋转的局部四元数差、相对缩放比例。
- 层输入不会因后续编辑被改变，合成也不修改源姿态或底层；权重 0 和空掩码不会声明新的创作通道。结果保留演员的肘膝弯曲模式。
- 不兼容骨架、无效的加法缩放参考、数值溢出等会整层跳过并返回带层索引的诊断；不允许在失败前局部修改结果。RigPose.overlay 保持原有严格兼容性校验和轻量覆盖路径。
- ActorRigPoseComposition 已将已有 authored 资产接入合成器，当前使用权重 1 的 OVERRIDE，保留“程序化底层 → 快速姿态 → 稀疏关键帧”的行为；运行时诊断进入现有演员诊断入口。
- 当前尚未增加片段的混合设置、淡入淡出、持久化或 UI 控件。基础 API 支持权重/掩码/加法，不等于用户已能在界面配置多层动画；下一步在原演员片段内部接入这些创作设置，不新增可见演员片段。


## 2026-10-21 原演员片段的骨骼动作混合设置

- 原 Spawn 属性新增“骨骼动作混合”：覆盖/叠加、0–1 权重、位置/旋转/缩放通道、全部或指定骨骼。这些设置归属原演员片段，不新增可见轨道或动画片段；尚无骨骼关键帧时提示创建后生效。
- 新增不可变 PoseBlendSettings，以骨骼 ID 保存作用范围；明确区分“所有部位”和“未选任何部位”。叠加当前固定以骨架绑定姿态为参考，不提供尚未实现的参考帧选择。
- Spawn 内嵌引用与独立逐骨骼 Animation 引用均持久化设置，并传入 EntitySample、实时合成和历史道具位置采样。旧式非逐骨骼动画不展示不可生效的混合控件。
- 属性手势通过草稿和已有命令链提交，支持撤销/重做。独立 Animation 的源、资产 ID、循环与速度也纳入同一事务；保留已有事件。Spawn 动画绑定变化会使待提交草稿失效，避免覆盖新的绑定。
- 足接触保护仅考虑权重非零、在部位范围内且存在选中创作通道的骨骼；被排除的通道或权重为零不再阻止程序化足接触。
- 新增 9 项验证，演员、实体、骨架及混合设置共 491 项回归通过（0 失败），编译及 diff 格式检查通过。未执行原生游戏视觉验收。
- 本轮仍是一份骨骼动画引用的混合设置，并非多资产层堆栈编辑器；淡入淡出、权重关键帧和逐通道足接触保护继续作为后续工作。

### 游戏内验收

1. 给玩家演员沿路径移动，并在原 Spawn 的头部旋转通道设置关键帧；选中原片段，在属性中展开“骨骼动作混合”。
2. 权重从 1 调到 0：手工姿态逐渐减弱，恢复底层姿态；路径位置不变，也不出现新片段。
3. 关闭“所有部位”，仅选择头部和旋转通道：头部接受关键帧，未选中的手臂/腿部继续底层动作；清空部位选择时该层完全不生效。
4. 切换“叠加”：以绑定姿态计算偏移；对已有底层旋转的部位核验与“覆盖”的差别。
5. 撤销/重做，并保存后关闭重开 Director：检查设置、原动画绑定和片段数量均保持一致。


## 2026-10-21 骨骼动作淡入淡出

- 原演员片段“骨骼动作混合”新增淡入/淡出时长（秒），默认 0；沿用原 Spawn 内嵌动画引用，无新增可见轨道或片段。覆盖与叠加均使用“标称权重 × 片段过渡包络”。
- 采用 smoothstep 平滑曲线，过渡只取决于片段本地时间与当前时长，不取决于上一帧、动画资产循环或播放速度。时长改变后即时重算；淡入与淡出总时长超过片段长度时按比例缩短，仍能达到标称权重。
- EntitySample 分开保留原混合设置与解析后的 animationBlendEnvelope；实时播放、无事件快照查询、历史道具位置合成均接入同一包络。旋转继续四元数 slerp，位置/缩放按通道插值，未创作通道不受影响。
- 足底接触从二元“保护/不保护”改为按实际创作权重逐渐让出修正量，避免过渡端点从 0 到非零权重时突然开关约束；指定骨骼集合的原入口继续等价于权重 1。
- 淡入/淡出随混合设置一起保存，并纳入已有属性草稿和命令事务，可撤销/重做。负值及非有限时长拒绝提交；有限但超过片段长度的时长允许输入并按比例求解。
- 新增 9 项回归，相关测试共 500 项通过（0 失败/错误），编译与 diff 格式检查通过；本轮未启动游戏做视觉验收。
- 范围：这是当前逐骨骼动画与底层动作之间的淡入淡出，不包含两个资产引用之间的自动交叉淡化、惯性化根运动或可打关键帧的权重曲线。片段重叠仍沿用原有引用选择规则。

### 游戏内验收

1. 在原演员 Spawn 的手臂旋转通道添加抬手关键帧，保持腿部未创作并沿路径行走。
2. 选中原片段，展开“骨骼动作混合”，设置淡入 0.3 秒、淡出 0.4 秒；检查手臂逐渐接管和释放底层摆臂，其他部位继续行走。若 Spawn 同时结束，演员仍按片段显示区间退出，不会因淡出延长存活。
3. 回拖、跳转到相同时刻并暂停，对照连续播放的姿态；调整片段位置、长度后过渡应同步。
4. 把两项时长之和设置得大于片段长度，检查过渡连续且仍能达到设置权重；将时长归零恢复即时混合。
5. 对腿部设置关键帧并淡入淡出，检查足接触修正没有端点开关跳变；撤销/重做、保存后重开，核验参数、动画引用和片段数量。

## 2026-10-21 数值姿态草稿与动画混合一致性

- 修复数值姿态草稿在最终姿态之后直接覆盖的问题：草稿现在只修改当前资产的 authored 输入，然后经过权重、淡入淡出、骨骼/通道范围、足接触与注视约束。数值应用前与写入关键帧后的混合结果保持一致，不再绕过这些设置。
- 预览同时核对演员、资产 ID 和骨架；同一演员上另一个同骨架资产不会错误接收当前数值草稿。草稿仅作瞬时输入，不改资产及历史，应用后沿用原关键帧命令。
- 提供当前已采样帧的姿态刷新入口，数值修改、应用、取消时只重算姿态、约束及自定义模型位置，不调用事件采样或动作派发；根偏移从采样坐标重新起算，避免连续刷新累加位移。播放头不匹配或存在竞争 Gizmo 手势时不抢写预览。
