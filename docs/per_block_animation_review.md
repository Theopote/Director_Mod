# 逐块动画机制检查（2026-10-12）

## 两种机制

整体动画对容器使用一个共享变换。逐块动画先由序列层决定各块的次序、分组和窗口，再由单块动作层在各自窗口内采样变换、透明度和特效。两者使用独立的时间计算。

此前按「片段长度减去一个单块动作」铺开所有开始时间，会让串行动作重叠；动作占满片段时甚至全部同时开始。现改为 PerBlockSchedule 累计完整动作，再统一适配片段总长。旧的「时间不够就全部同时动画」描述不适用于新的调度。

## 累计规则

以下 d 为单块实际动作时长，g 为实际等待间隔，D 为动画延迟和序列全局延迟之和。

| 模式 | 片段总长 | 行为 |
| --- | --- | --- |
| 串行 | D + N × d | 上一块完成后下一块启动 |
| 同时 | D + d | 每块独立采样，同时启动 |
| 批次 | D + B × d + (B − 1) × g | 批内同时，上一批完成后等待 g |
| 层并行 | D + 最大层方块数 × d | 各层并行，层内串行，短层提前完成 |
| 分组优先 / 交错 | D + N × d + (组数 − 1) × g | 各组按实际块数累计；交错反转相邻组的内部顺序 |

瞬时模式没有动作窗口，仍保留序列触发节奏；首块在延迟结束时触发，末块在片段结束时触发。单块或全部同时的瞬时序列在延迟结束时触发。

修改片段总长：保持完整动作和次序，统一缩放动作与等待间隔，延迟仍按秒设置。例如三块串行、每块 2 秒，总长 6 秒；把片段缩成 3 秒后每块完整执行 1 秒。

修改单块动作时长、序列并发或等待间隔：按累计规则重新计算片段长度。属性面板显示缩放后的实际动作时长和间隔。大型容器允许单块动作短于一个游戏 tick；配置复制和 Gson 保存保留短时长。

调度条目的开始位置和窗口比例由同一份计划生成；渲染可见性、动作进度和音效使用同一窗口。调度缓存区分瞬时与连续动作；时间为零的首块也包含在可见前缀中。

## 排序检查

普通串行按 Flow + Fill + Weight 的综合评分排序；固定层号排序此前会覆盖反向和低层级权重的效果。分组模式按层推进，反向同时改变组序和内部评分顺序。泛洪断开分量和同分条目使用稳定的位置选择。

## 游戏内验收

1. 三块普通容器：串行、单块 1 秒，片段应为 3 秒；首块落位后第二块开始，末块完整完成。拆除容器同样检查。
2. 将总长从 3 秒缩到 1.5 秒：每块执行完整的 0.5 秒动作，不能截断或全部同时启动。
3. 五块、每批两块、单块 1 秒、批间隔 0.5 秒：总长应为 4 秒，批次开始在 0、1.5、3 秒。
4. 两层分别一块与三块：层并行总长为三块动作累计；短层先完成。
5. 不等长分组，设置组间隔，确认上一组最后一块完成后才进入下一组；交错只改变组内方向。
6. 反向、低层级分离度、泛洪孤立区域，确认次序及重复播放一致。
7. 出现与拆除、瞬时与连续动作之间切换；暂停、拖动时间、重播，观察声音和特效对齐。
8. 短单块时长保存后重载；整体/逐块切换后的撤销恢复原片段长度。
9. 大选区观察帧率及真实方块交接，仍需游戏内画面验收。

## 验证范围

自动测试覆盖累计规则、所有并发与映射组合、不等长组、整体变速、延迟、出现/拆除采样端点、瞬时节奏、声音对齐、反向/权重、短时长复制保存，以及整体动画和模式切换撤销回归。只编译和运行测试，不打包 JAR。自动测试不能替代游戏内画面和性能验收。
