# 演员系统缺口审计与实施顺序

日期：2026-10-08。依据当前工作区代码；本报告不代表游戏内验收。补充 actor_system_development_spec.md 与历史阶段核对。

## 一、已有基础，不应重复开发

- 演员类型：玩家、村民、牛、羊、僵尸、骷髅、自定义。ActorCapabilities 与 ActorBehaviorCapabilities 已提供骨架、动作、道具支持查询，但尚非完整物种注册表。
- 玩家预览已使用真实玩家模型；宽臂/窄臂外观配置已接入保存。PlayerActorModelMixin 应用六个身体部位及外层皮肤。
- 人形与已绑定自定义骨架有关键帧资产、骨骼行、动作表、资产时间映射和姿态编辑；BoneRayPicker 与 ActorBoneSelectionController 已有场景骨骼控制点选择。
- 路径、地面检查、关系约束已有实现。ActorRouteClip 短跳高度限制为 1.25 格、时长限制为 0.1–0.8 秒；不是完全没有跳跃功能。
- 道具挂接、卸下、更换、投掷，时间跳转后的状态重建，以及人形挂点已有实现。
- 群体操作具备预检、跳过原因、延迟与单条批量历史命令；目前生成成员片段。
- 演员浏览器和属性面板已分工；删除确认已移到全局弹窗层。二者实际布局、模态输入和显示仍待客户端复验。

## 二、确定缺口与交付边界

| 内容 | 当前证据 | 待实现内容 | 优先级 |
| --- | --- | --- | --- |
| 演员实例删除撤销 | ActorProjectPropertyAdapter.deleteActor 直接 removeTrack/removeActor，删除皮肤文件 | 统一事务快照恢复实例、轨道、分组成员、选择与外观；皮肤资源不能在可撤销期间直接永久删除 | P0 |
| 实例编辑历史 | 名称、类型、皮肤、模型等存在直接设置并保存入口 | 按入口审计并统一命令；避免时间线可撤销但演员身份参数不可撤销 | P0 |
| 注视动态目标 | EntityClipSampler 复制模式、UUID和世界点；ActorRuntimeController.applyLookAt 只读取 lookAtPoint；Visualizer 对 ENTITY_UUID 返回未实现 | 相机、项目演员和世界实体的目标解析；明确采样时间、缺失目标与循环关系；运行时与标记共用解析结果 | P0 |
| 初始状态与动画编辑模式 | 放置有出生片段，整体编辑可生成变换片段；注视已改显式创建 | 明确初始摆放/修改现有行为/录制关键帧的目标和创建规则；不能只靠“不要新增片段”隐藏模型问题 | P0 |
| 模型与骨架矩阵一致 | 玩家模型逐部位应用 localTransform；挂点使用 RigWorldPose | 核对身体父变换传给头、四肢的结果，与挂点及控制点保持一致；目前不能称完整父子骨架渲染 | P1 |
| 部位选择体验 | BoneRayPicker 对骨骼位置做射线距离阈值拾取 | 可见部位的体积选择、遮挡/重叠优先级、根对象与部位模式提示；当前不是模型表面精确选择 | P1 |
| 村民/四足绑定 | ActorRigCompatibility.resolveRig 对两类返回空，过程动作另有基础 | 最小身体和头部绑定；可用动作与限制按类别提供，不必一次提供玩家式全部肢体 | P1 |
| 道具挂点范围 | ActorPropSocketResolver 限制人形拓扑 | 通用挂点定义、自定义骨架挂点、窄臂握持偏移；单独验证渲染/挂点坐标一致 | P1 |
| 双手搬运 | BOTH_HANDS 使用双手位置中点，明确非 IK | 物体为主/手臂为主的控制规则，双手接触与穿模策略；中点挂接不等于双手抓握约束 | P2 |
| 双演员交接 | 道具状态主要按单演员重建 | 稳定道具实例 ID、唯一所有权、跨演员转移事件和时间跳转重建，防止同物体重复出现 | P2 |
| 群体持续编辑 | ActorGroupTimelineCommandService 将操作分解为成员片段 | 生成来源ID、成员覆盖、再次生成保护、解除关联和烘焙；修改分组参数不能误宣称会更新已生成行为 | P2 |
| 物种与运动域 | ActorType 无禽类/飞行动物；现有路径重点为地面 | 物种定义注册表、鸟类基础、飞行/水域约束与按物种配置跳跃；不能仅扩充枚举就宣称支持飞行 | P3 |
| 高级骨架 | 现有人形为原版部位，未提供肘膝关节 | 新骨架版本、IK、重定向与约束烘焙；保持旧资产兼容 | P3 |

P0 表示先保证数据和交互可信，P1 表示核心制作能力，P2 表示协作与持续编辑，P3 表示扩展。不是所有条目都需要立即实现。

## 三、下一轮建议顺序及验收条件

1. **删除及实例属性历史**：从删除开始；一个操作一个命令，撤销同时恢复轨道、实例、分组关系与皮肤。确认取消不写数据；重做不重复产生轨道；外观文件可恢复。
2. **动态注视闭环**：先接相机与项目演员，再处理世界实体。播放头往返、目标移动或删除时结果明确；标记与头部朝向一致；从已选引用修改不额外创建片段。
3. **初始状态与记录模式**：界面显示当前写入对象及影响范围。摆放/修改现有行为/新增动画采用明确入口；选中出生与变换片段时不串写。
4. **玩家矩阵与部位选择校准**：身体转动时检查四肢、装备和控制点是否一起变；宽/窄臂同时测试。先修坐标一致性，再扩展骨架。
5. **村民、四足的最小绑定**：身体移动、头部转向、过程走跑足够形成第一阶段；能力查询、轨道行和属性一致。
6. **道具与群体持续编辑**：先定义来源与所有权的数据，再做搬运、交接和重生成界面。

## 四、需要游戏复验而非判定未实现的项目

- 删除确认能否始终显示、Esc/关闭后鼠标是否恢复。
- 玩家实时旋转方向、注视左右方向、窄臂换肤、外层皮肤和装备跟随。
- 变换草稿、锁定、播放头切换与撤销的预览清理。
- 动态时间线详情、世界/轨道/片段选择目标，以及只读状态提示。
- 地面路径、短跳、坡度/净空失败提示和牛羊头部动作。
- 道具在拾取、放下、投掷前后任意跳时的显示一致性。

用户已反馈整体移动流畅、抖动解决、撤销开始有效；不能由此推断所有撤销入口或所有物种都已验收。本次仅核对代码和文档，不运行游戏，不以旧测试数量覆盖这些缺口。
