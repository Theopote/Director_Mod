# 演员框架回顾与下一阶段计划

日期：2026-10-23。基于当前工作区源码静态审查；包含尚未提交的行走接触求解改动。本文区分已确认的代码缺口、由代码推导的风险和待游戏内验证的效果，不将最近 636 项回归通过等同于完整产品验收。

## 修复状态（本轮实施后）

- A1：已提取纯 ActorGazeConstraint；零权重不写回，部分权重从原头部旋转 slerp，玩家使用实际渲染头部基准和祖先变换；原生生物保留角度混合。测试覆盖父旋转和非等比缩放，游戏内视觉仍待验收。
- A2：已统一枚举独立动画、Spawn 手工动画、Spawn 预设引用；类型切换检查现代骨骼资产及固定人形预设，包括静音和非当前时间片段。未知/缺失资产的完整加载诊断仍属于后续工作。
- A3：群体路径快照复制已保留 smoothTravel 和 endpointTurnDuration，并验证撤销/重做。关联路径＋编队偏移的新模式尚未实施，当前快照语义保持。
- A4：负向膝盖改用同方向候选与合法增量范围，避免反向角度造成 clamp 下界大于上界；覆盖两种弯曲模式、不同负角度和部分权重。
- B1/B2 已完成第一阶段：ActorPoseEvaluator 共用骨骼合成与足接触，显式接收动画/草稿快照；实时与历史发射挂点均接入。世界根落点、注视、资产采样和调用方 UI 依赖尚未全部统一。
- 下文保留审查时的问题描述作为依据。其余 B/C 项仍待继续推进；没有把完整结构重构或游戏验收标记为完成。

## 1. 结论

保留现有演员资产、时间线片段、逐骨骼通道合成的基础。下一阶段首先统一姿态求解与约束，再扩展生物类别和作者功能。继续只打磨玩家步态会让类型校验、道具、群体命令等旁路逐渐落后。

现行产品约定保持：演员片段决定显示区间；路径按用户绘制的三维曲线运动；新建骨骼关键帧不新增可见演员片段；预设和手工动画独立；手工控制只覆盖实际声明的骨骼×通道；无旧文件兼容要求。

## 2. 现有框架与成熟程度

| 部分 | 当前事实 | 仍需闭环 |
| --- | --- | --- |
| 演员资产 | Actor/Registry、皮肤、自定义骨架和模型已有独立数据 | 类型变化时检查所有资产依赖 |
| 生命周期 | ActorTrack 引用演员，Spawn 决定存在区间 | 多入口加载/重绑定的一致性验收 |
| 整体运动 | 根 TRS 关键帧、路径、关系、整体 Gizmo | 明确冲突归属并在 UI 显示最终来源 |
| 骨骼动画 | AnimationAsset/BoneTrack；Spawn 内预设与手工动画独立 | 历史与实时使用同一求解管线；动作接续 |
| 合成 | RigPoseComposer 支持稀疏通道、权重、覆盖/叠加 | 调度仍是预设+手工两层及快捷姿态，而非完整作者层栈 |
| 过程化运动 | 物种 profile、距离相位、起停、走跑混合、玩家端点换脚 | 非玩家渲染绑定与物种专属动作覆盖不足 |
| 足接触 | 玩家使用限幅数值旋转求解；其他适配骨架保留原修正 | 连续性、性能、脚掌朝向、不可达目标反馈 |
| 注视 | 世界目标、演员目标、强度、后置更新 | 正确混合已有头部动画，并换算父骨骼空间 |
| 道具 | 多槽位挂点、双手中点、时间线事件、历史发射挂点 | 双手握持约束、历史与实时姿态一致 |
| 群体 | 编队、错峰动作、批量路径命令和事务已有实现 | 新增路径参数复制、路径关联和编队编辑语义 |
| 交互 | 统一演员选择入口、骨骼选择、时间线子行、Gizmo、草稿 | 实际控制来源反馈与真正求解结果一致 |
| 保存 | 时间线、演员、动画、骨架、模型分别保存 | 工程级一致快照、失败恢复和引用诊断 |

当前内置 ActorType 仅 PLAYER、VILLAGER、COW、SHEEP、ZOMBIE、SKELETON、CUSTOM。没有内置禽类/飞行类。RigDefinitions 提供玩家关节骨架、标准人形和自定义骨架；村民、四足类型仍没有可编辑的独立骨架绑定。不能因为有 RigProfile 就宣称已有可编辑骨骼。

## 3. 优先问题及证据

### A1. 注视的部分权重没有保留已有头部动作（高优先级，已确认）

位置：`src/main/java/com/director/actor/runtime/ActorRuntimeController.java`，`applyLookAt`。

当前将目标相对 yaw/pitch 乘 strength 后，用新的四元数直接替换头旋转。因此 strength=0 仍可能写入单位旋转；strength=0.5 也不是当前动画与目标旋转的混合。UI 所描述的“部分注视＋手工动画”与实现不一致。

同时只减去演员整体 yaw，没有逆变换 body/根骨骼已经产生的父级旋转。扭腰、侧身、缩放后的头部目标需要使用实际世界头部/眼睛位置与父变换计算。

验收：0 权重完全保持原头部动画；0.5 权重为从原姿态向约束目标的旋转混合；1 权重朝向正确；body 三轴旋转时仍能看向同一世界点；头部道具与实时/离线结果一致。

### A2. 更换演员类型的依赖校验遗漏 Spawn 内引用（高优先级，已确认）

位置：`actor/rig/ActorRigCompatibility.java`，`canChangeType`。

只遍历顶层 EntityAnimationClip。没有检查 EntitySpawnClip.boneAnimationId 与 preset.animationId，而这些正是现在主要的手工动画、预设存储位置。可能允许类型变更，之后相关动画被兼容性过滤，用户感受为动作消失。

建议统一 ActorAnimationReferences 查询，服务类型变更、删除资产、独立化、复制和加载诊断；避免每个入口重新枚举引用种类。动画目的类型变化时也应检查道具槽位和关系能力。

验收：仅有 Spawn 内动画的玩家不能无提示切到不兼容物种；清除/替换绑定可撤销；不需要存档迁移器。

### A3. 群体复制路径遗漏新参数（高优先级，已确认）

位置：`ui/actor/group/ActorGroupTimelineCommandService.java`，`copyRouteClip`。

手工逐项复制 speed/interpolation/loop/align/jump/waypoints，但未复制 smoothTravel、endpointTurnDuration。群体成员因此可能丢失加减速或端点转身。sourcePathId 也未保留，路径点被做成偏移快照；这是否符合群体命令预期需明确，不直接断言快照本身是错误。

建议建立统一 RouteSettings 复制/偏移策略，明确“关联路径＋编队偏移”与“复制独立轨迹”两种语义。

验收：源演员和成员的行进时间规则、转身时长一致；偏移策略明确；撤销恢复绑定与参数；修改源路径后的传播符合所选模式。

### A4. IK 对负向膝关节弯曲的范围处理存在异常风险（高优先级，代码推导）

位置：`actor/runtime/ActorLegContactIk.java`，坐标搜索的 Math.clamp。

膝角增量下界为 max(-0.9, -encoded.x)，上界固定 0.9。当输入 encoded.x < -0.9 时下界会大于上界，可能抛异常。完整手工权重通常跳过接触，但低权重、淡入或叠加层仍可进入此路径，不能只验证默认正向膝盖。

下一次修改应先补负向弯曲、方向角和低权重回归，再明确允许的膝关节方向；不应为了求解便利悄悄反转用户动作。

### B1. 实时与历史姿态管线重复（结构问题，已确认）

位置：`actor/runtime/ActorRuntimeController.java`，`applyRigProfile` 与 `samplePropLaunchTransform`。

两处分别进行 profile、步态、关节、预设、手工、快捷姿态和根偏移。历史道具采样没有完整复用实时的足接触和后置注视步骤；HEAD 槽位或未来脚部挂点尤其需要一致。普通手持物品不一定每次都出现差异，不能把所有道具都判为当前已错。

目标：纯 ActorPoseEvaluator(actor, sample, inputs) -> ActorEvaluationResult；返回整体变换、最终骨骼、实际控制来源、挂点和诊断。预览、拾取、属性反馈、历史查询和导出都消费它；世界实体创建、事件派发仍分离。

### B2. 运行时依赖 UI 单例（结构问题，已确认）

applyRigProfile、applyLookAt 直接读取 Gizmo、数值面板和草稿单例。离线/历史求解对“当前交互草稿是否应参与”没有统一的输入契约。

建议由编辑器提供可选 DraftSnapshot，EvaluationMode 明确 committed/interactive/export。约束、合成器不直接查询 UI；草稿只覆盖目标演员、片段、资产和通道。

### B3. 足接触尚非完整足部系统（能力缺口，已确认）

ArticulatedPlayerRig 只有大腿/小腿，没有独立脚或踝骨。当前可以改变脚底端点位置，但无法在任意屈膝姿态下独立控制脚掌朝向。不要通过额外改动膝盖假装实现脚掌锁定。

应先决定脚/踝控制采用真实骨骼还是渲染专用末端自由度，再接入时间线、拾取、网格和道具挂点。路径忠实模式继续按三维曲线运动；贴地和地形 IK 若添加，应是明确可选约束。

数值求解已有固定工作上限，但仍反复构造候选姿态、四元数和矩阵。没有多人场景帧耗时和分配率数据，不能以单元测试耗时证明其能支持群体。

### B4. 层内包络不等于动作接续（能力缺口，已确认）

RigPoseComposer 可组合多层，但片段采样仍为若干类别选一个活动片段，再把一个预设和手工层传给运行时。独立动画 applyAnimation 仍选最后开始者。不能把现有覆盖/叠加和淡入淡出宣称为任意动作的多层交叉过渡。

下一阶段需要明确动作引用、局部修正、叠加效果、过渡区间；不通过新增重复可见演员片段解决。先支持一个预设接续另一个预设，再考虑任意作者层栈。

### B5. 能力描述应成为单一来源（能力缺口，已确认）

ActorCapabilities、ActorBehaviorCapabilities、ActorRigCompatibility、RigProfile.supports 和 runtime 中 PLAYER 特判共同决定能力。ActorType 不是越加越好，需要数据化定义：运动方式、编辑骨骼、关节自由度、挂点、步幅、碰撞尺寸、渲染适配器。

扩展顺序建议：村民（头/身体/手臂组合）→ 四足（头/身体/四肢）→ 禽类/飞行（翅膀、飞行姿态）→ 更特殊的怪物。复杂玩家仍提供更完整的肘膝和未来手脚控制，基础交互保持同一套。

### C1. 引用和多文件保存需要工程级验收（可靠性风险）

TimelineModel.save 依次保存时间线、演员、动画、骨架和模型并合并布尔结果；它不是跨文件事务。单个文件的安全写入也不能保证跨文件引用处于同一个版本。

建议增加工程保存清单/快照批次、加载引用检查、失败重试与恢复；先补故障注入和重新打开工程验收，再确定具体存储设计。

### C2. 交互/选择需要结果级验收（待验收，不据此断言已坏）

已有 ActorSelectionHub、骨骼世界查询、草稿失效和关键帧子行。应集中验证：世界点选↔子行选择↔属性目标↔Gizmo↔轮廓是否同一个对象；切片段、删演员、换皮肤/骨架、切世界、撤销后是否还引用旧对象。

## 4. 应保留而不是推倒的部分

- Actor 与预览实体分离；Registry 作为工程资产入口。
- Spawn 内手工动画和预设独立引用，避免编辑时新建可见演员片段。
- 稀疏骨骼×TRS 通道与四元数旋转合成。
- 距离相位与表演时间分离，不把步态简单烘焙成固定时间周期。
- sampleSnapshot 与播放事件分离，不用历史查询消费播放触发缓存。
- 当前实时入口已由 renderWorld 前的 UIPlaybackBridge 按渲染帧驱动，不能再次误诊为固定 20Hz；导出时该入口会让出，另用 TimelinePlaybackSampler。
- 群体批量编队和错峰命令已有实现，下一阶段应补完整性，不能笼统写成“群体功能尚未实现”。

## 5. 建议执行顺序

1. **正确性补丁**：注视混合/父空间、IK 负向角度、类型切换引用校验、群体路径参数复制。每项都先做针对性回归，不把它们混进大型重构。
2. **统一姿态求解**：提取纯 evaluator；实时、历史挂点、拾取/反馈与导出对齐。保留明确的编辑草稿模式和无事件查询模式。
3. **完整验收场景与性能基线**：同一玩家路径行走＋挥手＋手工转头＋局部缩放＋注视＋手持/投掷；正放/倒放/跳帧/导出/保存重开对照。记录 1/10/30 个演员的求解耗时与分配率，先测量再定预算。
4. **补非玩家能力**：村民和四足渲染骨架绑定、局部拾取/轨道/动作一致性，统一 capability 描述；群体复用。
5. **高级作者功能**：脚/踝自由度、双手握持约束、动作过渡、复制/镜像/姿态库、曲线编辑。每项围绕上述统一求解入口实现。

## 6. 验收底线

- 调整演员不自动增加重复演员片段或轨道；删除生命周期片段后世界中不残留。
- 手工姿态、低权重预设、注视和接触都有可解释的最终贡献；0 权重必须无影响。
- 相同场景时间、工程数据和显式求解模式得到相同结果，不依赖播放历史。
- 带父骨骼旋转和非等比缩放时，显示、拾取、Gizmo、挂点仍对齐。
- 换演员类型/骨架或删除动画前检查全部引用；保存重开仍可选中、编辑和撤销新操作。
- 群体命令完整保留对应的路径运动设置，关联与快照行为明确。
- 自动测试、游戏内视觉验收、导出一致性和性能测试分别记录；不互相替代。
