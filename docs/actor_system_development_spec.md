# Director 演员系统开发规格与实施路线

版本：1.0（设计基线）  
日期：2026-10-01  
代码基线：`c7cafa94`，以本次检查的工作区内容为准。  
适用范围：演员创建、场景交互、动画、移动、道具、群体行为、时间线、属性面板及持久化。

本文区分 **已实现基础**、**已发现缺口** 和 **目标设计**。目标设计中的类名是拟议接口，不代表仓库已存在。本文作为后续演员开发的主规格；旧路线图保留技术背景，完成状态以实现记录和实际代码为准。

## 1. 核心决策

1. 使用统一的场景时间线。演员类型决定可展开的部位、通道、动作和属性，不为每种生物创建另一套时间系统。
2. 用户分类、骨架结构和移动能力分别定义。鸡属于禽类但不因此获得持续飞行能力；自定义模型也不能因为没有类型信息就默认使用人形动作。
3. 简单演员以“移动、朝向、转头、基础行为”为默认入口；玩家角色增加肢体摆姿、动画资产、装备和高级约束。两者共享选择、撤销和时间线规则。
4. 主时间线负责场景编排；演员部位子行负责直接打帧；动画详情区负责精细编辑。三个视图编辑同一份数据，不维护三份关键帧。
5. 群体第一阶段继续生成成员片段，但必须是一次可撤销事务、有兼容检查、有来源信息。后续再引入可持续编辑的群体行为层。
6. 所有动画结果由明确的时间和数据决定。回退、跳转、循环、重新打开工程必须重现同一状态，不能依赖 Minecraft AI 或播放时才触发的事件。
7. 每个操作必须清楚显示正在编辑“演员实例”“部位”“片段”还是“共享动画资产”。不能让同一个 Gizmo 随自动打帧开关改变写入对象。

### 2.2 必须先解决的结构性问题

- `ActorBoneGizmoController` 当前以自动关键帧开关分流：开启写动画资产，关闭编辑旧 `ActorPoseClip`。应改成显式编辑目标，自动打帧只决定何时提交关键帧。
- 部分创建入口（例如 `ActorTrackClipAuthoringService`）直接修改数据、标脏，缺少与其他编辑入口一致的锁定、兼容与撤销流程。
- `ActorGroupTimelineCommandService` 的批量动作会替换成员动作区间；需要在任何写入前完成整组检查，保存所有成员前态。
- 当前路径地形处理在 Runtime 中覆盖位置，而采样器又先处理路径、变换和关系。应定义最终位置的唯一求值流程，避免源之间相互覆盖后得到悬空位置。
- 预览实体关闭 AI、关闭重力，因此“看起来是牛/村民”不能保证动作、注视、地面接触自然。需要实体级绑定和验收。
- 新旧 `Pose`、`AnimationData`、`AnimationAsset` 以及两个 `Actor` 模型仍并存。保留读取兼容，新增功能应逐步统一写入通用骨架与新资产。

## 4. 演员分类与能力体系

### 4.1 三个维度

**浏览分类**回答“用户要创建什么”；**骨架/绑定**回答“哪些部位能动”；**能力**回答“这个实例可以怎样运动和表演”。三者不能用一个枚举替代。

建议保留 `ActorType` 读取旧工程，逐步引入稳定 `ActorDefinitionId` 和定义注册表。一个定义可以对应原版实体、自定义模型或项目模板；用户分类只用于浏览和筛选。不得使用枚举 ordinal 作为新增持久化 ID。

### 4.2 用户分类、首批内容和默认行为

下表为目标支持范围，除现有七类型外均为计划，不在实现前开放创建入口。

| 浏览分类 | 首批/后续实例 | 默认可见行为 | 细节编辑 |
| --- | --- | --- | --- |
| 人物 | 玩家角色（现有）；细臂/标准臂为外观变体 | 待机、走、跑、转身、转头 | 完整已有肢体、皮肤、装备；后续坐下、挥手、双手搬运 |
| 村民与类人 NPC | 村民（现有）；后续流浪商人等 | 地面移动、注视、转头、点头 | 默认头与身体；交叉手臂按模型真实结构控制 |
| 四足动物 | 牛、羊（现有）；优先猪，再狼/猫/马 | 走、跑、短跳、转头；吃草等按物种开放 | 默认整体和头；高级展开真实前后四腿及实际存在的尾/耳 |
| 禽类 | 优先鸡；后续鹦鹉 | 鸡：走、跑、短跳、啄食、短时扑翼；鹦鹉按绑定验证后开放飞行 | 头、身体、双翼与双腿按模型声明 |
| 怪物 | 僵尸、骷髅（现有）；后续苦力怕、蜘蛛 | 移动、注视、对应攻击/警戒；骨架动画按实际绑定 | “怪物”是浏览标签；蜘蛛不能套用人形腿或四足模板 |
| 飞行生物 | 后续蝙蝠等 | 起飞、飞行、悬停、降落按物种支持 | 飞行能力不由分类名称推断 |
| 水生生物 | 后续鱼、海豚等 | 水域游动、转向、升降；离水表现按定义 | 水域验证、身体/鳍/尾真实部件 |
| 自定义角色与构件 | 已有 Blockbench 方块模型；后续项目模板 | 仅显示模型、绑定和行为提供者已实现的能力 | 自定义骨骼、挂点、可动构件；缺失绑定显示诊断 |

不要把“能走、能跑”和“姿态动画改变位置”混为一谈。移动来源负责位移；步态负责外观。跳跃同时包含轨迹和身体表现，不能只播放抬腿姿势。

### 4.3 拟议能力描述

`ActorDefinition`：稳定 ID、显示名/分类标签、外观变体、模型提供者、骨架 ID、绑定 ID、默认能力与行为提供者。

`ActorCapabilities`：

- 移动模式：GROUND、FLIGHT、SWIM，可具有多种，但片段明确选择其中一种。
- 地面参数：体积、步高、最大落差、最大短跳高度/时长；速度范围。
- 控制部位：稳定部位 ID、父子层级、展示名、允许 TRS 通道、实际轴限位。
- 行为集合：已实现的行为 ID、所需部位、占用通道、是否改变世界位置。
- 挂点集合：左/右手、口部、背部等；不存在手的演员不显示“左手装备”。
- 外观能力：皮肤、变体、颜色、幼体等，逐个实现后才开放。
- 编辑能力：简单控制、骨骼编辑、构件编辑、镜像、可烘焙等。

`ActorBinding` 负责把通用姿态写入真实模型、提供部位世界矩阵和拾取体积。只有能力声明、绑定、采样、渲染、持久化和验收均完成的功能，才能标记为可用。

### 4.4 行为层次

- 基础行为：待机、走、跑、转头等，默认自动匹配移动速度。
- 导演行为：注视某点、跟随、沿路径、短跳、到达后停止等，显式编排。
- 姿态动画：演员骨架内的部位关键帧，不隐式改变世界路径。
- 道具行为：握持、拿起、携带、放下、交接。以挂接状态和物体轨道实现。

行为定义必须声明输入、时长策略、占用通道和适用能力。优先复用 IDLE/WALK/RUN 等现有语义，避免为每个物种复制整个编辑器。动物首版满足位置和头部控制即可，其余程序动作按需求逐步补充。

## 5. 场景放置与选择交互

### 5.1 创建流程

创建类型/模板 → 查看可用能力与模型预览 → 鼠标放置预览 → 点击确认 → 原子创建演员、绑定轨道与初始存在区间 → 选中新演员。

- Esc 取消放置，取消不遗留演员、轨道、预览实体或皮肤文件。
- 地面演员显示地面落点；飞行演员显示高度和飞行模式；无效位置给出可见原因。
- 创建时使用播放头时间；存在区间和初始位置分开表达，不能把移动演员误当作重新创建演员。
- 已存在演员的“重新放置”应编辑初始位置或当前时刻位置，先显示明确目标。不能无提示改写 Spawn。

### 5.2 三种明确模式

| 模式 | 点击对象 | Gizmo 编辑对象 | 可见反馈 |
| --- | --- | --- | --- |
| 整体 | 演员外形/边界 | 演员实例世界位置、朝向、缩放 | 整体轮廓、演员名、世界坐标 |
| 姿态/构件 | 当前演员可控制的部位 | 部位局部 TRS | 骨骼/构件高亮、层级路径、局部坐标 |
| 路径 | 路径及路径点 | 路径点和路径方向 | 路径线、点号、地形/移动模式诊断 |

工具条显示“整体 / 姿态 / 路径”，移动、旋转、缩放作为当前模式内的操作。骨架不支持姿态时入口显示原因；模式不得被打开属性面板自动改变。

点击部位子行可以进入姿态模式；点击演员父行进入整体模式。点击片段只切换片段编辑上下文，不自动改为摆姿。跨演员部位多选首版不支持，同一演员 Ctrl 切换部位多选，最后一个为活动部位。

### 5.3 拾取与手势规则

- 命中优先级：正在操作的 Gizmo → 当前模式控制点 → 当前演员部位 → 演员整体 → 世界对象。UI 遮挡区域不透传。
- 遮挡部位默认不可穿透选择；可通过层级树选取。未来“穿透选择”必须显式开关。
- 多个重叠演员提供候选列表，不能仅靠不稳定的实体遍历顺序。
- 暂不支持部位时，整体选择仍可用；不存在的挂点/骨骼不产生虚假的 Gizmo。
- 手势开始冻结工程、演员、轨道、片段、部位、时间和通道。拖动使用预览草稿；松开提交一个命令；Esc 恢复前态。
- 拖动期间切换对象、模式、时间或工程应取消未提交手势。锁定/删除目标同样取消。后续所有入口遵循此规则。
- 保持现有整体拖动的逐渲染帧交互；骨骼和路径也应保持流畅。数据只在提交时发出持久化变更，不每帧保存。

## 6. 统一选择与编辑上下文

拟议 `ActorEditContext` 为 UI 共用的编辑上下文，内容至少包含：

```text
projectId, timelineId
selectedActorIds, activeActorId, activeTrackId
mode: OBJECT | POSE | PATH
selectedPartIds, activePartId
selectedClipIds, activeClipId
selectedKeyIds
editTarget: INSTANCE | CLIP_LOCAL | SHARED_ASSET
timelineTime, assetLocalTime（若适用）
contextRevision, readOnlyReason
```

先以现有 `ActorSelectionHub` 为外观入口，将 `SelectionManager`、骨骼选择、路径选择逐步收拢。持久化模型不保存鼠标悬停、Gizmo 拖动或选中关键帧。

必须支持“工程内存在但当前时间线未使用”的演员：资产列表可选中它的基础属性，视口与时间线显示未绑定状态，提供“添加到当前时间线”。不能因没有轨道就清空资产选择。

上下文切换顺序：结束/取消草稿 → 校验目标 → 更新选择 → 生成能力与轨道描述 → 更新属性与工具。一个上下文修订只刷新一次，避免面板互相回写选择导致循环。

属性解析优先级：选中关键帧 > 选中片段 > 活动部位 > 群体 > 演员整体 > 工程。多选优先显示共同可编辑属性，并显示不一致值；“固定属性对象”只能通过明确的固定按钮启用。

## 7. 动态时间线：核心工作流

### 7.1 一个场景时钟、两种时间显示

主时间线始终使用工程时间。动画资产有局部时间和帧率换算，但不拥有独立运行的播放头；详情编辑器跟随工程播放头，也可在明确的资产预览模式下单独播放。

世界位置、存在状态、行为、动画片段、关系和道具挂接均归属于演员实例时间线。身体子行是同一数据的视图，首版不新增一条真实 `TimelineTrack` 对应一根骨骼。

### 7.2 默认轨道结构

```text
演员：Steve
  整体移动 / 路径             [沿路走────────]
  行为                        [走] [停止] [挥手]
  身体动画                    [挥手动画资产───]
  部位                        （按需展开）
    头                         ◇    ◇
    身体                       ◇
    左臂                       ◇  ◇  ◇
      旋转                     ◇  ◇  ◇
    右臂、左腿、右腿
  注视与关系                  [看向村民──────]
  道具                        [右手：剑──────]
  存在与可见性                [存在──────────]
```

牛的默认结构只显示整体、行为、头部、存在与可见性；高级展开时出现经绑定验证的四腿。自定义构件使用模型自己的层级。所有名称来自稳定 ID 对应的本地化展示，禁止硬编码七个人形部位。

父行汇总关键帧只负责提示和选中，不直接把聚合点当作唯一关键帧写入。空通道默认折叠，用户可“显示可打帧部位”；详情模式提供“仅所选部位”“仅有关键帧”“搜索”。显示状态与动画数据分开保存。

### 7.3 根据选择自动切换

| 用户选择 | 时间线/详情 | 属性面板 |
| --- | --- | --- |
| 玩家整体 | 玩家父行与总体行为 | 外观摘要、世界变换、已有动作入口 |
| 玩家左臂 | 高亮左臂及支持的通道 | 局部旋转/缩放、打帧范围、挂点入口 |
| 牛整体 | 地面路径与基础行为 | 地面移动、速度、短跳参数 |
| 牛头 | 头部关键帧或已实现头部控制 | 转头角度、注视限位；不显示人形手臂 |
| 路径片段/点 | 路径段与点选择 | 移动模式、速度、地形检查、路径点 |
| 动画片段 | 资产 Dope Sheet，可见裁剪区间 | 资产、速度、循环、局部时间和共享状态 |
| 关键帧 | 对应部位/通道及时间 | 值、插值、移动/删除；锁定则只读 |
| 群体 | 群体汇总与成员行 | 成员、队形、行为、延迟、例外 |
| 不同类型多选 | 共同轨道/属性 | 共同能力；逐对象报告不适用项 |

将当前固定 `ActorTimelineAnimationPanel` 改为上下文详情容器，移除重复的演员列表。可折叠、拖动高度、弹出为独立窗口；无选择时给出任务提示。用户不必为了看骨骼数值持续增大主时间线。

### 7.4 打帧与编辑目标

- “修改通道”：只写本次变更的通道，默认方式。
- “所选部位”：写已选部位的支持通道。
- “全身”：显式命令，写当前骨架的可编辑通道。
- 自动打帧默认关闭。关闭时先保存预览草稿，提供“打帧 / 应用到当前静态姿态 / 取消”，不偷偷写另一种片段。
- Gizmo、数值输入、快捷键和轨道菜单使用相同编辑服务、目标定位和撤销事务。
- 播放状态下默认禁止姿态写入；进入录制模式属于后续单独功能。

首次制作实例动作时一键创建项目内动画资产并绑定当前片段；已引用共享资产时默认编辑实例副本，提供明确的“编辑共享资产（影响 N 个引用）”。复制与绑定必须是一个事务，撤销同时清理新资产和引用。

现有“全身打帧”采样的是资产局部姿态。未来“烘焙当前可见结果”作为独立功能，明确包含程序动作、约束和路径；不能让用户误认为两者等价。

### 7.5 时间与冲突规则

- 主时间线按工程帧吸附；资产内部按局部帧吸附。工具提示同时显示工程时间与资产时间。
- 播放映射以单一服务处理：片段起点、速度、源起点、裁剪、循环/往返。当前只已有部分字段，缺失字段按阶段补齐。
- 循环实例投影出来的多个点引用同一个资产键。第一阶段循环投影只定位，进入资产编辑后修改；后续允许拖动时必须明确影响所有重复周期。
- 拖动落到已有键默认拒绝，明确提示冲突；替换、合并作为显式选项。跨部位粘贴校验骨架、部位和通道。
- 父行汇总、子行、Dope Sheet 共用键 ID、选择集合与编辑命令。不能因视图切换丢失正在编辑的目标。
- 片段重叠第一阶段禁止同一位置来源的含糊覆盖；高级姿态混合只有声明权重、通道 Mask 和顺序后才开放。

## 8. 移动、注视与姿态求值

### 8.1 世界位置与局部姿态分开

世界移动使用实例轨道；骨架 Root 平移是局部动画偏移。基础步态使用原地动画，路径负责前进。Root Motion 首版不自动提取到路径，后续增加显式转换/烘焙命令。

拟议求值流程：

1. 存在区间与基础实例变换。
2. 世界移动源：路径或直接位置关键帧；同一时刻选择一个主源。
3. 群体移动基准与成员局部覆盖（群体行为层启用后）。
4. 空间关系约束：跟随、相对位置等，按依赖图求值。
5. 移动模式验证：地面/飞行/水域；检查包含将参与最终位置的 Root 偏移。
6. 骨架绑定姿态 → 程序步态 → 关键帧动画 → 显式导演覆盖。
7. 部位约束：头部注视、后续手脚 IK，遵守模型限位。
8. 最终矩阵、道具挂接和渲染。

对依赖环、自身跟随、互相循环挂接给出诊断。求值依赖目标同一时间的状态，不能用目标实体上一帧的位置造成随遍历顺序变化。

### 8.2 地面与飞行规则

- GROUND：沿地面移动，有步高、落差和身体净空检查；短跳是受限的独立运动段。跳高/时长由能力决定，当前 1.25 格和 0.8 秒上限只是现有默认。
- FLIGHT：使用三维路径和净空检查；起降点、倾斜和扑翼行为按物种声明。鸡默认不能持续飞行。
- SWIM：轨迹落在允许水域；水面/离水行为显式定义。
- 导演可启用“自由动画移动”突破现实限制，必须在片段标识，防止普通地面模式无意悬空。
- 路径资产保存意图，地形编译结果保存缓存。世界变化、区块未加载、能力或身体尺寸变化使缓存失效。
- 无效路径显示红色区段和原因，默认停在最后有效点；没有有效起点时显示幽灵诊断。避免只让演员消失而用户不知原因。
- 注视分为“整体朝向”和“头部看向”。默认注视改头部，超出限位可选择带动身体；现有简化 yaw/pitch 行为需逐绑定替换。

## 9. 玩家角色的复杂度管理

玩家入口名称使用“玩家角色”，说明它是导演预览角色，不接管真人玩家。外观、基础行为与高级动画分层呈现。

默认界面：皮肤、整体移动、头部、常用姿态、手持物。高级展开：七部位完整 TRS、动画资产、镜像、通道 Mask、约束与曲线。

标准臂/细臂、帽层/外层衣物必须与模型绑定和皮肤尺寸校验配套。当前已有皮肤导入与纹理管理，但变体入口需单独验证后加入。

现有标准人形没有肘膝关节。首版实现 Minecraft 原版肢体旋转，不承诺真实双骨骼 IK；需要可弯曲模型时新增独立骨架版本和模型绑定，旧七部位动画继续可播放。人形怪物可以复用通过验证的骨架，UI 仍显示它们自己的外观与能力，不强制显示玩家皮肤设置。

## 10. 手持物、搬运和交接

道具是独立可动画对象，绑定到演员挂点后从最终部位矩阵计算世界变换：

```text
道具世界矩阵 = 演员世界矩阵 × 骨骼累计矩阵 × 挂点局部矩阵 × 道具局部偏移
```

第一阶段：左右手单手握持，支持物品/方块选择、偏移、旋转、比例和持续时间。道具 UI 同时支持视口选择与时间线挂接行。

第二阶段：拿起 → 携带 → 放下。挂接区间由时间求值，拿起/放下保留世界变换；任意跳转能恢复正确拥有者、位置和可见性，不能只在跨越事件那一帧 attach/detach。

第三阶段：双手搬运与交接。一个手为主挂点，另一个手通过已支持的约束或摆姿对齐。交接在同一事务中改变物体拥有者与前后世界变换，避免出现两个副本。没有 IK 时明确提供手工摆姿方案。

`CARRY` 是携带姿态，不负责自动创建物体；`PASS_OBJECT` 关系名称也不代表道具转移已实现。现有道具运行时应先接上骨骼矩阵和渲染，再开放完整行为菜单。

## 11. 群体行为

### 11.1 分清三个概念

- 选择集合：临时多选，用于一次编辑，不写入群体资产。
- 演员组：持久化成员和组织关系，成员仍有独立演员身份与轨道。
- 群体行为：一段时间内的共同动作、路径、队形与差异规则。

一个演员可加入多个组织组，但同一时刻不能存在两个未解决的群体位置控制源。行为冲突显式报告；组织分组不自动控制成员位置。

### 11.2 阶段一：可靠的批量编排

复用现有队形/延迟/成员片段生成。先显示预检结果：可执行成员、不支持动作、锁定、无轨道、缺资产与冲突。默认只对通过检查的成员执行，但用户在提交前必须看见明确数量。

整组操作一个命令，包含成员片段替换与轨道包装器同步；Esc/失败保持前态。生成记录保存操作 ID、成员、来源组、参数、种子和生成片段 ID。再次生成不得静默删除成员的独立修改。

异构群体通过语义行为匹配：玩家/牛共同前进可用同一移动意图，但步态不同；“挥手”只对有对应能力的成员执行；骨骼动画资产必须通过骨架兼容校验。

### 11.3 阶段二：可持续编辑的群体行为层

拟议 `GroupBehaviorClip`：组引用、成员快照、行为、队形、路径、延迟策略、固定种子、成员例外。成员快照防止之后增删组员使既有镜头无提示改变；显式“同步当前成员”更新快照。

群体生成基准 → 成员相对偏移/时间差 → 成员显式通道覆盖。手动编辑成员仅覆盖所改通道；可恢复跟随群体，也可“解除生成关联”或“烘焙到成员片段”。UI 显示生成内容与独立内容来源。

队形沿路径在路径切线坐标中计算，而非只平移源路径。FOLLOW_LEADER 使用领导者历史弧长/时间位置，不能仅把每人向后偏移几个方块。转弯与不同体型、速度需要单独验收。

固定随机种子控制相位、速度、姿态变化；绑定到成员稳定 ID，成员顺序变化不应无意重随机。真实避障、拥挤求解、群鸟模拟属于后续，先做可重现的导演队形。

## 12. UI 信息架构

| 界面 | 主要职责 | 动态内容 |
| --- | --- | --- |
| 演员库 | 创建、搜索、类型/模板、实例、显示、锁定、组织分组 | 能力徽标、未使用/缺资产状态 |
| 资产库 | 动画、姿态预设、路径、皮肤、模型、道具 | 按当前演员兼容性过滤；显示引用与副本关系 |
| 场景视口 | 放置、整体/部位/路径操作 | 当前模式、选中高亮、挂点与地形诊断 |
| 主时间线 | 实例编排、部位子行、群体汇总 | 当前对象支持的通道与片段菜单 |
| 上下文属性 | 当前对象、片段、部位、键、群体 | 能力驱动字段；世界/局部单位和编辑目标 |
| 动画详情 | Dope Sheet，后续曲线 | 当前资产或片段的局部通道；可弹出与固定 |

项目模板、演员实例和动作资产分别展示，复制演员时明确“共享动作资产 / 复制动作资产”。列表“隐藏预览”仅是编辑器状态；时间线“可见性”属于作品数据；锁定禁止编辑但不停止播放；静音片段改变求值。这些状态不能共用一个开关。

将笔刷和自动打帧移到时间线/工具栏，把群体行为移到群体上下文，将演员属性里的资产列表改为快捷摘要和入口。所有新增文案进入 i18n，不继续散落硬编码中文或底层类名。

## 13. 架构落点与数据兼容

拟议数据流：

```text
ActorDefinition + Actor实例 + ActorBinding
                    ↓ 能力解析
ActorEditContext → TrackDescriptor / PropertyDescriptor
                    ↓ 操作命令
实例片段 + AnimationAsset + GroupBehavior + Attachment区间
                    ↓ 同一时间求值
世界移动 → 关系 → 移动验证 → RigPose → 部位约束 → 挂点 → 渲染
```

| 现有模块 | 演进方向 |
| --- | --- |
| `ActorType` / `ActorRigCompatibility` | 引入定义和能力解析，旧类型映射到稳定定义 ID |
| `ActorSelectionHub` / 部位选择 / UI Selection | 共用 `ActorEditContext`，保留旧入口适配 |
| `ActorBoneTimelineRows` / `TimelineRowLayout` | 能力生成 `TrackDescriptor`，复用现有动态高度与命中 |
| `ActorTimelineAnimationPanel` / 属性 adapters | 使用上下文路由，不重复维护演员选择 |
| `ActorBoneGizmoController` / 编辑服务 | 显式目标、预览草稿、统一事务、取消与只读检查 |
| `EntityClipSampler` / `ActorRuntimeController` | 拆出纯求值与绑定提交，集中解决来源顺序与确定性 |
| `ActorGroupTimelineCommandService` | 先补事务和来源，再接群体行为资产 |
| `ActorPropRuntime` / `RuntimeProp` | 最终矩阵挂接和时间区间状态，完成渲染 |

新增存档必须有 schemaVersion 和逐版本迁移。旧 `ActorType`、旧 `ActorPoseClip`、旧动画库继续读取；旧静态/姿态配置转换不得静默丢弃通道。未知定义、骨架或资产以占位显示并保留原始引用，允许修复，不能直接删除对象。

编辑器子行和展开状态不迁移成真实轨道；必要的视图状态保存于独立工程 UI 状态。求值缓存以工程/资产修订、绑定/能力版本、地形修订为键，编辑提交后才失效。

## 14. 分阶段任务与完成标准

每阶段先完成可验证的端到端场景，再扩展物种数量。没有人工验收记录的功能标记“代码已实现、待场景验收”，不得标记完成。

| 阶段 | 任务 | 依赖 | 完成标准 |
| --- | --- | --- | --- |
| P0 一致性 | 固定编辑目标；冻结手势上下文；统一锁定/撤销；群体批量预检与事务；清理重复创建入口 | 现有代码 | 切对象/切时间/Esc 不误写；每次操作一次撤销；锁定入口一致 |
| P1 能力与选择 | 定义注册表、能力解析、统一上下文；兼容资产诊断；未绑定演员可选；UI 分层 | P0 | 三个现有样本：玩家、牛、村民拥有正确菜单/只读原因，无无效部位 |
| P2 动态时间线 | 统一子行与 Dope Sheet 键选择；上下文属性；详情区改造；片段时间映射和实例副本 | P1 | 从父行到部位到键全过程一致；两个演员互不误编辑；共享影响清楚 |
| P3 基础物种闭环 | 玩家绑定验收；牛羊四足与村民头部绑定；移动/注视求值；再加入猪与鸡 | P1、P2 | 牛沿地面走并转头，村民移动并注视，鸡不会持续悬空；保存回读一致 |
| P4 道具闭环 | 单手挂接、道具渲染、挂接区间、拿起放下；再扩展搬运交接 | 玩家最终矩阵、P2 | 挥臂时物体跟手；任意跳转拥有者/位置正确；一次撤销完整操作 |
| P5 群体闭环 | 可靠批量生成→群体行为层、来源和成员覆盖；沿路径队形 | P0 事务、P3 移动 | 多类型同路移动，单成员例外不丢失；固定种子重播一致 |
| P6 高级扩展 | 飞行/水域、曲线、动画混合、真实关节/IK、重定向 | 对应绑定与求值完成 | 每个新能力都有渲染、编辑、存档和场景样本；按单能力验收 |

道具与群体在依赖满足后可分别推进，不必等待所有物种或高级曲线。不得继续以增加枚举和显示按钮代替端到端支持。

### 下一轮可直接执行的任务单

1. 梳理所有演员写入入口，形成“锁定、目标、撤销、持久化”检查表；优先修复骨骼 Gizmo 自动打帧改变数据目标的问题。
2. 为群体动作/路径/放置命令增加前后态、预检与一事务撤销，明确报告跳过成员。
3. 引入最小能力描述，先包装现有类型/骨架，不改变旧存档；用同一结果过滤动作、部位、挂点与片段菜单。
4. 引入编辑上下文适配器，接通演员父行、部位子行、视口和属性；补未绑定资产选择和多选共同属性。
5. 将固定动画详情区改成随选择切换的容器，并统一编辑目标提示。
6. 选择玩家、牛、村民三场景，记录渲染问题后再安排新生物与道具绑定。

## 15. 验收与测试清单

自动测试重点：能力解析/绑定兼容；上下文切换和手势取消；工程与资产时间映射；稀疏通道保持；位置来源/约束顺序；批量事务回滚；挂接区间任意时间采样；固定种子；旧工程迁移。

复用现有 `RigPoseTest`、`ActorRigCompatibilityTest`、`ActorKeyframeProjectionTest`、`TimelineRowLayoutTest`、`ActorAnimationKeyframeEditingTest`、`ActorGroupTimelineCommandServiceTest`、`GroundRouteTest` 与持久化测试。单元测试通过不能代替原版模型实际渲染验收。

| 场景 | 必验操作与结果 |
| --- | --- |
| 玩家挥手 | 创建/换皮肤，选左臂，两个关键姿态；只有左臂通道改变；播放/倒放/跳转/保存回读一致 |
| 牛走路转头 | 地面路径、短跳、头部控制；身体类型菜单正确，腿不出现人形命名，无长时间悬空 |
| 村民注视 | 沿地面移动并看目标；头部转向有合理限位，整体朝向不会被无提示替代 |
| 手持剑 | 手臂运动带动剑；整体移动、局部旋转和缩放均正确；取消/撤销不留道具残影 |
| 拿起和放下 | 在挂接区间前后任意跳转，物体拥有者和世界姿态正确且只有一个实例 |
| 异构群体 | 玩家、牛、村民一起走；挥手只匹配支持成员；锁定成员跳过且报告；一键撤销恢复全部 |
| 群体队列转弯 | 队形按路径切线/历史位置变化；独立成员调整保留；成员顺序不影响随机结果 |
| 切换上下文 | 拖动中切演员/播放头/工程、删除或锁定；不向新对象写入，不产生孤立资产 |
| UI 与性能 | 不同面板尺寸、缩放、长名称、重叠演员；单演员 Gizmo 连续顺畅，群体有分级显示与可测帧时间 |

性能先记录代表机器上的单演员、20 演员、100 演员基线，再设置可执行预算；不承诺未测量的固定数量。地形编译避免在每个演员每帧全量运行；骨架、矩阵、轨道行描述只按相关修订重建。
