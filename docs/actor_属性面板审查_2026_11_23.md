# 演员属性面板审查

日期：2026-11-23。审查对象是当前工作区 `0059f5e5`（`perf(actor): 缓存帧间重复采样以减少运行时开销`）。工作区另有 `gradle/wrapper` 的未提交改动，下面的结论不依赖这两处文件。

范围是属性面板里和演员有关的页面：工程概览上的添加演员、身份卡、分组、工具页（姿态、路径、变换）、轨道页，以及出场、变换、路线、注视、语义动作、姿态、状态、关系、动画、离场、一次性道具事件和整体键检查器。本轮按当前源码阅读，不把 `docs/actor_UI审查_2026_11_10.md`、`docs/actor_UI交互审查_2026_11_13.md` 里已经落地的条目再列成未修复问题。没有修改产品代码，没有启动 Minecraft，也没有在游戏里点过这些面板。

## 总评

片段检查器、轨道页和身份卡的分工已经稳住。名单点击只切换演员，轨道页能改名、静音、锁定并创建片段，路径库会打开路径工具，出生预设把主预设放在第二预设前面，状态页只留下发光和可见性。这些和当前源码一致。

还没对齐的是几处「面板写进去了，预览不读」或「面板显示的不是用户刚选的东西」：原版生物的皮肤导入、变换工具里的注视目标、路线正在接管时的缩放。姿态工具「更多」里有一节标题和实际创建的片段类型不一致。

## 已经核对、这次不列为问题

- 轨道页静音、锁定和「查看演员」仍走现有命令与 `ActorSelectionHub.selectActor`。名单点击不会退出姿态工具。
- 笔刷提示已写明时间线拖拽涂抹暂不可用。`TimelineActionPaintHandler.startActionPaint` 仍无调用方，按既有约定保持不接线。
- 平滑行进只在循环模式为单次时可以勾选。`ActorRouteMotion.once` 才读取这个标志；循环和往返用恒定速度，端点转身自己做平滑。禁用条件和采样一致。
- 跳跃高度会保存、复制，编辑会话也会带上，但播放采样不读它。可编辑的路线页没有跳跃控件，这和采样一致。只读失败页仍打印跳跃，见下面的 P2。
- 姿态片段的角度滑条按度显示、按弧度写回。状态页的可见性覆盖用勾选结果翻转草稿。路线路点删除按钮的禁用区间是配对的。
- 玩家肘膝弯曲只出现在玩家身份卡上，和现有步态能力一致。
- 村民、牛、羊的姿态片段页会说明当前骨架不支持旧版姿态覆盖。这是已定的能力边界。
- 动画片段的事件编辑在片段手势结束之后绘制，事件自己走 `ActorAnimationEventEditing.replace`。
- 动作风格滑条点「应用风格」才提交，走 `ActorAppearanceEditing.style`。
- 删除演员走 `ActorDeletionService`，确认文案写的是可以撤销。添加演员走放置流程，放置提交也是一条可撤销命令。`ActorProjectPropertyAdapter.createActorAndTrack` 现在没有调用方。

## 应修改

### P1：原版生物的身份卡可以导入皮肤，预览不会使用

身份卡在玩家专属的模型与肘膝弯曲之后，对所有类型都显示当前皮肤文件、「选择 PNG」和「清除」。导入会把相对路径写入 `skinFileName`，并可以撤销。

皮肤纹理只有两条读取路径：

- 玩家预览 `PreviewPlayerActorEntity.getSkin`。
- 自定义演员使用的盔甲架渲染 `ArmorStandRendererMixin`。`ActorPreviewManager.createActorEntity` 只让 `CUSTOM` 生成 `PreviewActorEntity`。

僵尸、骷髅、村民、牛、羊走 `NativeMobActorEntities`，用原版生物渲染，不读 `ActorSkinTextureManager`。在这些身份卡上选择 PNG 会成功保存，世界里的预览仍是原版贴图。

建议：原版生物身份卡不要提供玩家皮肤导入；若保留控件，写明当前类型不会更换贴图。玩家和自定义盔甲架可以继续使用这一节。

定位：`ActorProjectPropertyAdapter.renderActorSkinSection`；`ActorPreviewManager.createActorEntity`；`PreviewPlayerActorEntity.getSkin`；`ArmorStandRendererMixin.director$overridePreviewSkin`。

### P1：变换工具里选好的注视演员，收起下拉后变成 UUID

注视片段检查器会把目标 UUID 解析成演员名称，解析不到才显示「请选择目标」。变换工具的实时注视下拉不是这样。

收起时的标签是：

```166:166:src/main/java/com/director/ui/properties/actor/ActorLiveTransformPropertyUI.java
if(ImGui.beginCombo("注视目标演员",lookSource==null || lookSource.getTargetEntityUuid()==null?"请选择目标":lookSource.getTargetEntityUuid().toString())) {
```

展开后的每一项用的是 `candidate.getName()`。选中并提交时，`ActorNumericEditSession.updateEntityTarget` 写入的也是演员 ID，数据本身是对的。用户合上下拉之后，只能看到一串 UUID，无法确认刚才选的是谁。旁边的模式、强度和世界坐标已经走语言包，这一行标签和「请选择目标」仍是源码里的中文。

建议：与注视片段页相同，用注册表里的名称作为收起标签；演员已删除时再显示 UUID。

定位：`ActorLiveTransformPropertyUI` 注视小节；对照 `EntityLookAtClipPropertyAdapter` 里 `getActor(...).map(Actor::getName)`。

### P1：路线正在控制当前位置时，任意一条变换片段都会锁住实时缩放

变换工具在路线覆盖当前时间时，会禁用位置和朝向，并允许在出生片段上单独插入缩放关键帧。缩放是否禁用由下面这个条件决定：

```113:114:src/main/java/com/director/ui/properties/actor/ActorLiveTransformPropertyUI.java
boolean scaleBlocked = routeProtected && com.director.ui.actor.gizmo.ActorTransformEditSession.resolveSource(model, target.timelineTrack()) != null;
ImGui.beginDisabled(scaleBlocked);
```

`resolveSource` 并不表示「播放头正落在一条变换片段里」。当前时间没有命中时，它返回选中的变换片段，否则返回时间上最近的一条未静音变换片段。

因此轨道上只要曾经有过一条整体变换，播放头停在路线里时：

- 缩放输入被禁用；
- `root` 被解析成那条变换片段，而不是当前出生片段；
- 「路径控制位置和朝向；缩放可单独设置关键帧。」和「插入缩放关键帧」不会出现。

播放头这一刻并没有变换片段在接管缩放。路线页自己的整体键按钮会在路线占用时显示 `route_protected`，和这里的隐藏行为也不一样。

建议：只有当前时间真正落在未静音的变换片段内时才锁实时缩放。其余路线区间继续走出生片段的缩放关键帧。

定位：`ActorLiveTransformPropertyUI` 的 `scaleBlocked`；`ActorTransformEditSession.resolveSource`。

### P2：姿态工具「更多」里的「姿态片段」创建的是语义动作

姿态工具默认展开的是关键帧动画。收起的「更多」里，第一节标题是语言包里的「姿态片段」。这一节的下拉、强度、时长和循环交给 `createActorActionClip`，按钮文案是「在当前时间创建语义动作片段」。真正创建 `ActorPoseClip` 的是下一节「局部姿态覆盖」。

创建失败时，错误句子画在按钮后面，悬停提示却检查最后一项。失败之后，按钮上那句「创建的是 ActorActionClip」不会出现。

建议：把这一节改成语义动作的标题，或把它和局部姿态的标题对调到和按钮一致。失败原因留在页面上时，不要抢走按钮的悬停说明。

定位：`EditorToolPropertyAdapter.renderPoseAuthoring`；`zh_cn.json` 的 `tool_editor.pose_clip` 与 `pose_tool.create_action`。

### P2：沿路径移动的摘要直接打印循环枚举名

路线检查器的循环下拉和只读行使用 `routeLoopLabel`。同一块「沿路径移动」摘要把 `getLoopMode()` 拼进句子，界面上会看到 `ONCE`、`LOOP` 或 `PING_PONG`。这块摘要出现在路线片段页顶部，也出现在变换工具里。

建议：摘要使用 `ActorPropertyAdapterI18n.routeLoopLabel`。

定位：`ActorPathMovementPropertyUI.render` 中 `tr("summary")` 那一行。

### P2：整页整体键检查器在路线占用时只灰掉输入，不说明原因

时间线上打开整体键时，`ActorRootKeyPropertyUI` 在路线占用当前区间会禁用世界位置和整体朝向，缩放仍可编辑。页面上没有 `route_protected` 那句说明。片段页里的 `ActorRootKeyframePropertyUI` 在同一条件下会写出这句话。

路线编辑会话构造失败时的只读页仍打印跳跃起点、时长和高度。播放不读这些字段，可编辑页也没有跳跃控件。用户会把失败页上的数字理解成当前路线的跳跃。

建议：整页键检查器沿用片段页的路线说明。只读路线页不再把跳跃列成有效参数；采样仍忽略跳跃即可。

定位：`com.director.ui.timeline.render.ActorRootKeyPropertyUI`；`ActorRouteClipPropertyAdapter` 会话构造失败分支里的 `readonly_jump`。

## 建议的修改顺序

1. 原版生物身份卡停止提供无效的皮肤导入。
2. 实时注视的收起标签改为演员名称。
3. 路线区间的实时缩放只在当前时间确实有变换片段时锁定，否则保留出生片段的缩放关键帧。
4. 改姿态工具第一节标题、路径摘要的循环名称，以及整体键和路线失败页上的说明。
5. 再把上表里的句子收进 `zh_cn.json` 和 `en_us.json`。
