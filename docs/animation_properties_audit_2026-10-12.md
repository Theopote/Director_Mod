# 容器片段动画属性面板审查（2026-10-12）

## 范围

检查普通/拆除片段适配器、共用 TimelineClipPropertyUi、序列时间控件、整体动作/特效控件、声音刷新、整体编辑会话及其撤销历史。本轮以源码和逻辑测试审查为主，没有实际操作游戏内 ImGui 面板；窄面板布局、焦点与弹窗行为仍需游戏内验收。

## 已修复的问题

| 问题 | 修复 |
| --- | --- |
| 切换逐块动作或恢复默认值会清空 params 中的音效时机和偏移 | 将动作默认参数与片段级声音参数分开处理，保留声音和旧迁移标记；切换保留透明度修饰，重置只重置动作及修饰 |
| 显式并发模式已覆盖时间映射，面板仍让用户编辑无效参数 | 时间映射仅在依次启动时启用；批次/组间隔控件按运行时优先级显示，不删除用户原设置 |
| 瞬时逐块模式仍可编辑没有作用的动作时长/缓动 | 禁用相关控件并说明仅使用启动时刻；序列和动作启动延迟仍可编辑 |
| 拆除动画显示额外透明度渐变，运行时只在 ENTER 应用该修饰 | 在 EXIT 和瞬时模式隐藏该修饰，保留原有配置；原生退出动作仍有自身的淡出 |
| 逐块动作时长、序列延迟/间隔、透明度修饰拖动过程中未通知修改 | 这些控件在值变化时通知预览，松开也确认最终值 |
| 值变化时控件仍活跃，声音刷新被跳过；松开那一帧可能不再返回 modified | 将刷新请求保留至面板空闲时处理，限定在原模型中仍存在的片段；跨片段选择不会覆盖排队请求 |
| 从整体切回逐块后，保留的动画 delay 在逐块面板没有独立入口 | 增加动作启动延迟控件，明确与序列全局延迟相加，不改变启动间隔 |
| 同一个“动画时长”标签表达两种不同含义；片段长度提示仍暗示结束即全部完成 | 逐块明确为“单块动作时长”；片段提示区分逐块启动范围与整体有效动作范围，说明尾段可以超出片段 |
| 特效总标题带动态数量，数量变化会改变折叠状态的 ImGui ID；列表 ID 还包含可变索引 | 总标题使用稳定 ID，列表以特效 UUID 作为 ID |

## 仍需统一完善的编辑机制

### 1. 撤销覆盖不对称（最高优先级）

WholeContainerAnimationEditSession 仅在编辑前或编辑后为整体模式时记录动作会话，State 只包含 scope/mode/duration/delay/easing、整体变换及片段长度。

逐块模式下的动作参数、序列设置、特效增删/参数修改，以及基础设置并未接入同等的手势撤销。切换作用范围涉及逐块参数回退时，也没有完整的逐块 params 快照。用户会遇到“同样拖动参数，整体能撤销、逐块不能撤销”的不一致。

建议建立共用的 ClipPropertyEditSession：每次手势保存完整相关状态，拖动只预览，释放提交一个命令；撤销/重做统一刷新预览、尾段和声音。片段起点/长度、动画配置、序列与特效都应使用该机制。

### 2. 面板隐藏/选择变化的编辑收尾

当前 finishAnimationEditIfIdle 需要适配器继续被渲染。切换到其他对象、关闭属性面板或切换适配器时，不应依赖原面板下一次出现才结束未提交手势和声音刷新。

建议为属性适配器增加显式编辑结束生命周期，在选择改变、面板隐藏、工程切换时分别提交或丢弃原会话；工程切换不能把旧编辑写入新工程。

### 3. 两种作用范围共享时长/延迟/缓动

逐块 mode/params 和整体 transform 参数各自保存，但 duration/delay/easing 仍共享。在整体中调动作速度，切回逐块后可能发现单块时长与缓动也变了。若产品希望两种模式各自保留一套设置，需要独立存储并兼容旧存档，而不是只调整界面。

## 建议的面板结构

建议按用户决策顺序组织，先选“对谁做动画”，再选“如何动作”，最后调高级细节。保留目前特效预设和“不使用特效”的选择方式。

1. 顶部固定摘要：容器名、方块数、逐块/整体切换、出现/拆除标识。
2. **动作**（默认展开）：动画预设/动作类型、单块或整体动作时长、启动延迟、常用参数。
3. **顺序与节奏**（仅逐块，默认折叠高级参数）：方向/起点/常见启动方式；分层、权重、泛洪、批次与时间映射放在高级区。
4. **运动曲线**：缓动预设；整体的弹跳/弹性归在这里。高级强度、衰减、次数按选择显示。
5. **特效**：预设、无特效、强度与扩散；单项特效编辑留在高级区，不与基础动作参数混放。
6. **声音**（默认折叠）：只展示已生成声音的入口和有效时机，整体仍保持一个声音。
7. **片段与显示**（默认折叠）：起点、片段长度、颜色、遮挡透明和结束后淡化。

目前序列区在模式选择前，主要分区默认都展开；用户必须先读高级序列参数才能找到作用范围切换。建议先移动切换入口，再逐步改变默认展开策略，不同时大改所有控件。

## 时间信息应直接展示

逐块面板不应要求用户推算时间：普通依次启动时展示“每 0.2 秒启动一块 / 每块动作 1 秒 / 末块在 2.8 秒完成”，其他并发模式展示对应的实际启动和完成摘要。摘要应使用运行时调度结果，并缓存计算，避免每帧对几万块重新评分。

整体面板展示“设置动作时长 / 实际有效时长”，特别是延迟占用片段之后。duration 控件最大值目前按 clip.length 限制，而实际窗口按 clip.length - delay 限制；数值与实际动作存在差异。优先显示有效窗口，再评估是限制输入还是明确说明压缩规则。

基础起点/时长目前使用两个固定 80px 标签和两列输入，窄面板可能产生过小甚至负的输入宽度。建议宽度不足时改为纵向两行，使用可用内容宽度布局。

## 建议的落地顺序

1. 统一逐块/整体/序列/特效的手势撤销和面板收尾生命周期。
2. 模式选择移到顶部，显示真实启动节奏和完成时间摘要。
3. 收起高级参数，完善窄面板布局、整体有效时长提示、独立模式设置。
4. 再评估动画预设缩略图与预览入口，避免先增加更多参数。

## 验收

- 切换逐块动作、恢复动作默认后，已设置的声音时机和偏移保持不变。
- 同时启动/层并行时，时间映射不再可编辑；批次模式只展示真正起作用的批次设置。
- 瞬时模式仍可调启动延迟/序列，不能修改无效的动作时长与缓动。
- 拖动单块时长、延迟与间隔，暂停预览立即变化，松开后声音按最终值刷新。
- 从整体带延迟切回逐块，能看到和调整这份启动延迟。
- 增删特效后，特效面板和剩余特效的折叠状态保持稳定。
- 逐块与整体分别检查撤销、切换对象、关闭面板、保存重开，这些是下一阶段重点。
