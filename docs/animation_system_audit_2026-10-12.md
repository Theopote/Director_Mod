# 方块动画系统审查（2026-10-12）

## 范围与结论

本轮围绕逐块与整体容器动画，检查配置复制、项目存档、序列评分与启动调度、单块和整体时钟、播放/暂停/拖动/重播、真实方块与覆盖层交接、透明度、特效、关联声音、播放尾段及离线采样。演员系统只执行全量回归，没有改动演员实现。

逐块动画保持两个独立时钟：片段长度决定启动间隔，属性面板时长决定每块动作持续时间，动作允许重叠与超出片段右边界。整体动画仍使用自己的整组时间窗口。

本轮发现并修复了下列缺陷。代码检查和自动测试可以确认状态、时钟与存档行为，不能据此宣称游戏内渲染、光影兼容或大规模性能已经全部验收。

## 已修复

| 重力坍塌被反向采样 | EXIT 的通用反向规则将原本就是退出语义的重力坍塌变成反向动作 | 将 GRAVITY_FALL 作为原生退出动作，正常下落并淡出 |
| 旧渲染上下文仍裁剪单块窗口 | 旧 renderBlock API 仍把动作压进片段，提前拒绝尾段采样 | 使用 PerBlockAnimationTiming，共享独立动作窗口，并允许尾段与退出前静态状态 |

| 单块动作整段被一帧跨过 | 尚未建立单块特效门控时，完成采样认为是中间定位，漏发一次性特效 | 正常播放跨过单块开始时先记录启动跨越，完成采样仍能越过特效阈值；拖动不补发 |
| 整体声音随片段比例错误缩放 | 片段长度变化、实际落地时刻不变时，声音仍被移动 | 按新旧真实交接时刻的差移动声音，缩放预览与提交使用一致公式，保留用户声音偏移 |
| 整体瞬时效果不刷新音效 | 整体效果类型不在自动声音签名中，切换瞬时后可能保留旧声音时刻 | 把整体效果类型加入刷新签名 |
| 零缩放生成奇异矩阵 | 单轴生长或零比例模型在起点可能生成无穷法线或不可逆光照变换 | 使用极小非零比例保护缩放，测试法线和逆矩阵均为有限数 |
| 禁用落盘时不刷新动态尾段 | 离线采样/加载期间 suppressPersistenceWrites 使 markDirty 提前返回，动作时长修改可能保留旧尾段缓存 | 将时长缓存失效与磁盘写入分开，禁用写盘仍重算尾段 |

## 已核对、未确认新缺陷

- 序列配置复制：扫描轴、行距、蛇形往返位于 extraParams，现有 copy 会复制这些值，之前的怀疑已排除。
- 启动调度：依次、同时、批次、层并行、分组、交错均不依赖单块动作时长；反向顺序、权重与泛洪顺序继续使用现有序列逻辑。
- 当前主渲染路径使用时间线采样快照，拖动和播放共享动作状态；旧独立 API 的时间计算已同步修正。
- 整体动画的旋转、自定义轴心、组合通道、弧线路径、弹跳/弹性、透明度和冲击波已有回归测试，本轮未改变其动作公式。
- 主路径继续使用覆盖层独占与真实区块交接重建机制，没有重新引入同时绘制两份方块的逻辑。
- 同一容器只能绑定一个容器片段的约束存在于 TimelineTrack，控制器按容器保存一份状态符合这一约束。

## 后续优先项

### 1. 音效关联持久化（已确认缺陷，优先处理）

TimelineAudioService 的 blockSoundTimingByEventId 只在内存中保存所属方块和动作内偏移；TimelineModelPersistence 当前只保存声音时间、音量、音高、声音 ID 等属性。

重新加载时，rebuildAudioLinksFromTimeline 按音频片段时间范围重新关联声音，没有恢复所属方块。随后缩放逐块片段会退回整段比例换算，可能改变独立动作偏移，或把尾段声音夹到片段末尾。重叠的音频区间还可能关联同一个声音；用户取消关联的信息也没有持久化，重开后可能被重新关联。

建议为生成声音保存稳定来源（容器 / 所属方块 / 动作内偏移 / 明确的关联或取消关联状态），新项目按来源恢复；老项目只做可识别的迁移，无法确定归属的事件不要猜测。旧文件已经遗漏的数据无法从现有 JSON 准确恢复。

### 2. 多音频轨道的跟随（已确认代码路径缺口）

容器片段范围变更与声音预览使用 findAudioTrack 查找事件，而 moveLinkedEventsToTrack 允许把关联声音移到其他音频轨道。声音移到非首个轨道后，相关范围变更/预览路径可能找不到事件。

建议按事件 ID 查找实际所属轨道，而不是固定查询第一条音频轨道；与音效来源持久化一起补回归测试。

### 3. 瞬时逐块特效语义（需明确并统一）

INSTANT ENTER 的快照 rawProgress 仍默认 0，EXIT 分支不执行特效。非零归一化触发位置的预设在瞬时模式下可能没有效果。当前行为是显式特殊分支；建议统一为“在方块瞬时出现/消失时发射一次”，并分别检查 ENTER/EXIT 预设，避免仅改进度就重复发射持续特效。

### 4. 大规模容器与渲染实测（尚未进行本轮实测）

逐块覆盖层注册仍需要扫描序列；并发动作很多时，模型、环境光遮蔽与区块交接会增加帧成本。需要在真实游戏中测量，才能决定是否引入活动窗口索引、模型批次缓存或分帧预算优化。

建议测试小容器、1 万与 5 万块容器；分别观察整体组合变换、逐块密集并发、连续拖动、播放停止后的追平。记录帧时间和主线程开销，再决定优化方向。

## 游戏内验收建议

1. 保存并重开带分组/批次、全局延迟、非默认层距、特效与退出阶段的工程，确认设置和画面保持一致。
2. 重力坍塌从原位下落并逐渐淡出；逐块时长短于一帧时，一次性特效不应漏发或重复发射。
3. 反复循环、倒回、暂停、拖动和重播，检查特效恢复；拖动与暂停定位不应发射粒子。
4. 拉短整体片段但保留同一落地时刻，声音应保持在落地前；切换瞬时后声音移动到瞬时时刻。
5. 检查生长、展开在精确起点的画面，尤其植物、透明材质及已有光影环境。
6. 同一场景比较播放、拖动预览和离线逐帧导出在相同时间的方块姿态，检查尾段与真实方块交接。
