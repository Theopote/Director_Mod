# 演员界面交互审查

日期：2026-11-13。审查对象是当前工作区 `573b2082`（`feat(animation): 支持贝塞尔缓动 Y 值超出端点实现预备与回弹`）。工作区另有未提交删除 `docs/DIRECTOR_UI_UX_DESIGN_SPECIFICATION.md`，下面的结论不依赖这份文档。

范围是属性面板怎么切换、演员面板、出场预设、路径、时间线轨道和轨道片段的操作反馈。本轮按当前源码阅读，不把 `docs/actor_UI审查_2026_11_10.md` 里的旧问题原样再列一遍。没有修改产品代码，没有启动 Minecraft。

## 总评

轨道页、静音和片段检查器已经分开。点中演员轨道会打开轨道页，眼睛图标对演员轨道切换的是采样使用的静音，并且走撤销命令。出生片段用一组起止时间。骨骼关键帧松手后用 `ActorAnimationKeyClock.seek` 跳播放头。

还没对齐的是「创建一段表演」这条主路径。演员卡上的笔刷告诉用户去时间线上拖一段，这个拖拽没有入口。轨道页的 Action 按钮用的是同一支笔刷，失败时没有说明。右键菜单里的「行为 (Action)」又是另一种一次性事件片段。路径要先打开路径工具，库里点一行才会真正载入。

## 已经接上的交互

- 选中演员轨道时，`getContextTarget` 保留 `TimelineTrack`。`ActorTrackPropertyAdapter` 提供改名、静音、锁定、查看演员，以及播放头上的五种片段按钮。静音和锁定走 `ToggleTrackMuteCommand`、`ToggleTrackLockCommand`。
- 轨道头部的眼睛对演员轨道显示 `!isMuted()`，点击执行静音命令。锁也走命令。其他轨道的眼睛仍改 `visible`，而且那次点击不进撤销。
- 片段页顶部有「打开轨道」和片段静音。静音走 `StateChangeCommand`。播放、拖播放头、锁定和 Gizmo 拖动时，片段检查器保留参数并标明只读。
- 演员窗口停在默认布局左侧，和容器共用一列。名单、分组、路径库、场景诊断都在这里。属性面板空选择时是工程概览和「添加演员」，不再假装自己是浏览器。
- 演员档案收成名称、类型、外观、分组、放置和「打开姿态工具」。姿态图库在姿态工具里。实时变换和路径摘要在变换工具与路线片段页。
- 出生预设的范围说明收在可折叠节点里。第二预设不能以全权重盖住同一个主动作时，主预设下拉里对应项会被禁用。
- 姿态工具里创建语义动作或局部姿态失败时，会留下一句原因。

## 交互问题

### P1：笔刷文案要求的拖拽没有入口，轨道上的 Action 按钮失败时没有反馈

演员档案里「动作笔刷」的提示是：「在时间线的演员轨道上拖拽一段，即可创建某动作区间」。`TimelineActionPaintHandler.startActionPaint` 没有任何调用。`applyActionPaint` 会直接 `replaceActionClips`，不进命令；这段逻辑目前到不了用户手上。

笔刷的实际消费者是轨道页按钮。按钮文案在中文语言包里仍是 `Action`，提示是「使用当前 Action Brush 创建动作片段」。页面上不显示当前笔刷是哪一个。`ActorTrackClipAuthoringService.createClip` 在这些情况下返回 `null`：正在播放或拖播放头、轨道锁定或静音、动作不被该演员支持、已有未静音的语义动作与新区重叠。按钮忽略返回值，页面上没有任何句子。

姿态工具里的「在当前时间创建语义动作片段」是第三条入口。它能写出失败原因，但原因是硬编码中文，而且和轨道按钮、笔刷不是同一个表单。默认笔刷是 `RUN`。用户在档案里换了笔刷，再回到轨道页，看不到这个选择还在生效。

右键「创建实体片段」仍走 `AddEntityClipCommand`，和上面的服务各建各的：

| 入口 | 用户看到的名称 | 实际片段 | 默认时长 |
| --- | --- | --- | --- |
| 右键 | 出现/绑定 (Spawn) | `EntitySpawnClip` | 5 秒 |
| 右键 | 位移/旋转 (Transform) | `EntityTransformClip`，不采样当前位置 | 2 秒 |
| 右键 | 动画 (Animation) | `EntityAnimationClip` | 2 秒 |
| 右键 | 行为 (Action) | `EntityActionClip`，进入片段时触发一次交互/攻击等事件 | 0.5 秒 |
| 轨道页 / 笔刷设计 | Action | `ActorActionClip`，持续的跑、跳等语义 | 2 秒，默认循环 |
| 姿态工具 | 语义动作片段 | 同上，时长和循环来自表单 | 表单值 |
| 右键 | 状态 (State) | `EntityStateClip` | 2 秒 |
| 轨道页 | State | `EntityStateClip` | 3 秒 |

「行为 (Action)」和「Action」在界面上都像动作，采样却完全不同。轨道页能建的五种里没有出现、动画、离场、关系和路线。右键菜单里没有局部姿态和路线。变换片段只有轨道页那条会用当前采样播种起终点。

建议：时间线上的拖拽要么接到 `ActorTrackClipAuthoringService` 并撤销，要么改掉笔刷提示。轨道页按钮用中文动作名，并写出当前笔刷；`createClip` 返回 `null` 时把原因留在页面上，和姿态工具一样。右键与轨道页创建同一种片段时走同一服务。一次性事件不要再叫 Action。

定位：`ActorProjectPropertyAdapter.renderActionBrushSelector`；`zh_cn.json` 的 `brush_hint_fmt` 与 `actor_clip_action`；`TimelineActionPaintHandler`；`ActorTrackPropertyAdapter.renderActorClipButton`；`ActorTrackClipAuthoringService.createConfiguredClip`；`TimelineContextMenuFactory` 的 `ACTOR` 分支。

### P1：在演员名单里点一行会退出当前编辑

`ActorProjectPropertyAdapter.selectActor` 固定调用 `selectWholeActor`，然后再 `inspectActorObject`。`selectWholeActor` 每次都取消姿态草稿、清骨骼选择和整体键检查，并激活选择工具。名单里再次点中同一个人也会走完这套。

结果是：正在用姿态工具改骨骼时，点左侧名单会丢掉未提交草稿，属性面板变成演员档案。时间线虽然会选中该演员的轨道，档案的显式检查优先级更高，轨道页要再点一次轨道才出现。轨道页上的「查看演员」只调用 `selectWholeActor`，同样会清草稿，然后靠「当前没有其他工具」退回档案。

世界里点演员也是 `selectWholeActor`，用来退出骨骼选择是合理的。名单是另一块一直开着的面板，点它不应等于放弃姿态编辑。

建议：名单点击只切换 `currentActorId` 和轨道高亮。已经在姿态工具里时保留工具和草稿。需要档案时用明确的「编辑演员」。同一个人再次点中时不要取消草稿。

定位：`ActorProjectPropertyAdapter.selectActor`；`ActorSelectionHub.selectWholeActor`；`PropertiesPanel.renderInspector` 里对 `getActorInspection` 的提前返回。

### P1：路径库里点一行，工具没开时什么都不会发生

路径有三处入口，互相不说明状态：

1. 路径工具：画锚点，应用到当前演员，或存进路径库。未选演员时仍能画，应用按钮禁用。
2. 演员窗口「路径库」：点一行会调用 `loadPathForEditing`。该方法在 `ActorPathController.active == false` 时直接返回。行会显示成选中，没有错误，锚点也不会出现。锁定、重命名、删除的禁用原因是硬编码中文，而且不包含「请先打开路径工具」。
3. 变换工具里的实时变换，以及路线片段页顶部，都有 `ActorPathMovementPropertyUI`：从库里选一条再「应用 / 切换」。这条才会调用 `ActorPathEditing.attach` 或 `switchPath`。轨道页和右键菜单都不能新建路线。

`applyPathToSelectedActor` 在锚点不足时把「请先准备至少两个锚点，并选择可编辑的目标」写进 `lastError`。这句话只在路径工具页能看见。从库里点已锁定的路径时，控制器只打日志。

路线片段本身的检查器在只读时用硬编码句子，循环模式直接打印枚举名。时长输入不合法时静默弹回，没有 `gesture.report` 那种说明。来源路径仍绑定着时，插值和路点不可改，这点有提示；折返转身的标签和说明仍是硬编码中文。

建议：路径库的选中在工具未开启时写明原因，或直接激活路径工具再载入。新建路线放到轨道页，和「在播放头创建片段」放在一起。路线只读和非法时长使用语言包里的句子。

定位：`ActorPathLibraryPanel.renderPathRow`；`ActorPathController.loadPathForEditing`、`applyPathToSelectedActor`；`ActorPathEditAvailability.reason`；`ActorPathMovementPropertyUI`；`ActorRouteClipPropertyAdapter` 只读分支和时长输入。

### P2：多选片段会盖住单段检查器

选中不少于两个时间线对象时，`TimelineSelectionProperties.render` 直接占住属性面板。演员片段只能看到共同的名称和起止时间，不同则显示「—」，然后是「没有可批量编辑的字段」。摄像机关键帧另有批量字段。

因此多选两段演员片段时，片段静音、「打开轨道」和该类型自己的检查器都不会画。用户无法从这里改任何一段，也看不到为什么按钮不见了。

建议：演员片段多选至少提供统一静音，或者明确写出「请保留一段以继续编辑」，并留一个回到主选择的动作。不要在只有只读摘要时吞掉原来的检查器入口。

定位：`PropertiesPanel.renderInspector` 对 `TimelineSelectionProperties.render` 的调用；`TimelineSelectionProperties` 在非摄像机关键帧时的 `NO_BATCH_FIELDS`。

### P2：预设和状态页的反馈还差一层

出生页里「第二动作预设」树排在主预设下拉之前。第二层的混合说明又藏在下一层树里，主预设本身没有同等位置的一句「这是出场后一直使用的动作」。主预设下拉里被禁用的项没有悬停原因，用户看不到是因为和第二预设全权重重叠。

「独立成副本」失败时只在点击那一帧 `ImGui.setTooltip`。手稍离开按钮，原因就没了。其他失败路径会把句子留在面板上。

轨道页 State 的提示写着「可见性/潜行/发光等状态」。状态检查器里潜行、冲刺、无敌三个框被永久禁用，旁边才说明它们尚未接入预览。发光和可见性是真正能改的。提示把不能用的三项说成了这个按钮的用途。

建议：主预设在上，第二预设在下。禁用项用允许在禁用状态下显示的提示写出原因。副本失败写成停留在页面上的文字。状态按钮的提示只写发光和可见性；三个未接入的框可以从检查器拿掉，旧值仍由存档保留。

定位：`ActorSpawnPresetPropertyUI.render`、`renderSecondary`、`renderIndependentAction`；`zh_cn.json` 的 `actor_clip_state_tooltip`；`EntityStateClipPropertyAdapter`。

## 建议的操作顺序

用户要完成一次出场、走路和挥手时，界面宜收成这条线：

1. 在演员窗口点一名演员，只改变当前演员，不关闭正在用的工具。
2. 在轨道页看到静音、锁定，以及一组中文片段：出现、位移、动画、语义动作、局部姿态、状态、注视、离场、关系、路线。点下去要么出现片段，要么留下原因。
3. 语义动作的当前类型写在轨道页上。时间线上的拖拽如果保留，就使用这一个类型，并进入同一条撤销。
4. 右键菜单调用同一组创建，不再另做一套 0.5 秒的「行为 (Action)」。
5. 路径工具、路径库和路线页共用「当前是否在编辑库路径 / 路线 / 草稿」。库里点一行时，工具没开就说明，工具开了就载入锚点。

## 本轮不重复列出的旧结论

对照 `573b2082`，11 月 10 日报告里的这几条已经对上，不再当作缺陷：

- 点轨道却打开整份演员档案。
- 眼睛只改 `visible`、预览却看 `muted`。
- 轨道锁定直接写字段。
- 出生片段同时编辑结束时间和时长。
- 骨骼行松手按匀速公式跳播放头。
- 收起时间线面板就 `cancelTransientWork`。时间线隐藏现在只取消时间线自己的拖拽。换工程和重载仍会清草稿，这是换档，不是收起面板。
- 拖动 Gizmo 时片段检查器整页空白。

逻辑采样、存档和撤销的正确性仍以代码审查为准。本次只看用户点下去之后界面有没有接住。
